# DAA 工作台与启动设置

## 1. 目标与基线

沿用已确认的工作台预览，让工作台首先显示运行概览；操作者可以分别选择 DAA 软件下次启动时是否自动采集或上报。两项默认关闭，原有手动模式照常可用。现有 [原生启动](../../src-tauri/src/lib.rs) 会打开本机配置、恢复已激活版本，随后保持停态；采集已有逐 PLC 运行和重连，上报已有逐 PLC 的三项绑定、参与开关、逐份投递和可靠回执。沿用这两条运行链路。[本地存储合同](../../src-tauri/src/infrastructure/local_store/README.zh-CN.md) · [逐 PLC 上报](../DAA-013-multi-plc-reporting-identity/checklist.md)

## 2. 需求

1. **R01 工作台。** 顶部依次显示「已连接 PLC」「采集中 PLC」「本地待上报包」「容量准入」四张现有卡片，其下放独立的「启动设置」，再显示「上报运行」「采集运行」。启动设置标题可展开或折叠，折叠时仅留标题和展开入口；两项说明合为一个可通过鼠标悬停、键盘聚焦查看的问号。工作台移除「配置草稿」卡；配置中心（含「上报与存储」）保留原草稿保存、激活、版本详情与回滚入口。将工作台仍需的提示置于运行区域：保留真实的操作失败、刷新失败、未激活配置、未保存草稿等适用提示；刷新失败时标注状态不可用或过期，不把旧值或 `0` 当作新状态。
2. **R02 上报卡与顶栏。** 两个页面共用的「上报运行」卡将「实际上报地址」和「最近可靠确认时间」分别作为对齐的两行，长地址可读且不挤掉时间。主按钮停态为「启动上报」，运行时仍为「暂停上报」；保留手动启动的现有确认。DAA 顶栏移除「本地采集」「上报状态见页面」两个固定标签；它们不读取 PLC 或网络状态，与 `localhost` 无关。保留侧栏产品标识、顶栏操作和实际 PLC / 上报状态。界面沿用项目现有样式和中英文国际化。[当前 DAA 顶栏传参](../../src/App.vue)
3. **R03 开关与时机。** 「启动后自动采集」「启动后自动上报」独立，以当前 profile 的本地 SQLite 为准，直接操作开关，保存成功即反馈，不经过配置草稿、激活或手动启动弹窗。切换仅改变下次真正打开 DAA 原生应用时的行为；不会启动、暂停本次正在运行的任务，也不会因刷新、切页或激活配置重新触发。两项缺省为关；重开当前兼容 profile 时各自还原。手动暂停采集、断开 PLC 或暂停上报立即取消对应本次自动运行意图及还未执行的自动尝试；按现有规则收尾在途工作。再次打开应用时依已保存的两个开关处理，不记忆本次手动启停作为下次设置。显示设置/自动启动失败原因，手动路径保持可用。
4. **R04 自动采集。** 开关打开时，在本地运行器就绪、活动配置恢复后，按现有准入对已启用且具备有效采集组的 PLC 分别连接，连接成功后启动其已启用组。临时无法连接沿用逐 PLC 有界重连，恢复后自动开始；一台失败不阻塞其他台。没有已激活配置、没有可采集组、读取受限或存储不准入时尊重现有限制，显示原因。停用 PLC、草稿和启动之后才新增的配置不因旧启动任务自动打开。上报可独立启动。
5. **R05 自动上报。** 打开开关即选择下次按当前已保存的上报设置运行；切换时不加确认弹窗、不探测后端、不发送。每次启动从当前 profile 读取上报设置的同一有效快照，复用现有目标、合同、来源绑定和逐 PLC 参与检查；并发更改导致快照失效时重新核对，不使用过期配置派发。操作者以后显式保存的合规绑定和参与开关在下一次启动适用，无需再次操作总开关。按现有队列逐份发送符合条件的实时及待传样本；设置无效或身份不匹配时不派发相关样本并显示原因，禁用、未绑定、仅本地记录或待人工处理的样本继续遵守原规则。自动启动不得执行原本仅供手动确认的解除来源阻断或修改已冻结样本目标写入，包括已准备但尝试次数为 0 的样本。目标不一致且已有未结记录时，保留原目标、原身份和原正文，留待操作者按原流程核对；相同 URL 不证明后端数据库相同。仍仅由匹配回执确认。网络暂不可用沿用现有发送与重试；采集关闭时仍可独立发合格的既有待传样本。

## 4. 可核验的交付

| 编号 | 通过标准 |
| --- | --- |
| AC01 | 两个页面、两种语言下确认布局、折叠、鼠标与键盘帮助、动作按钮/原有手动确认、长地址和实际状态，配置中心保存、激活、版本详情和回滚没有退化。在模拟操作出错、状态失效和草稿未激活等状态下，仍能理解该做什么；顶栏只清理指定两项。 |
| AC02 | 用空白和既有兼容的合成 profile 核对默认停态、保留旧配置/样本和手动上报；模拟四种开关组合及关闭重开，证明只有相应工作启动。从兼容旧本地 profile 和设置读取/写入失败复核失败分支；切换时本次任务状态和草稿版本不变。 |
| AC03 | 两台合成 PLC 中一台暂不可达，另一台能先采；恢复后按现有准入开始采集。手动暂停/断开不被当次自动重试覆盖；下次启动才再按设置执行。缺少已激活配置或不具备采集条件时不发起相应动作。 |
| AC04 | 仅自动上报时逐份发送已参与且身份和目标匹配的待传样本，由匹配回执确认。显式保存一台新的合规参与 PLC 后，下次启动能发送其合格样本，无需重切总开关；未参与、未绑定、目标或身份不匹配和并发旧快照不误发。覆盖来源已阻断及目标变化后已准备、尝试次数为 0 的样本：来源阻断不清除，未结样本原目标、原身份和冻结正文不变，保留待手动核对。暂停后不产生新派发。 |
| AC05 | 运行与改动匹配的 Rust 检查/构建和前端检查/构建，记录启用的生产路径和夹具边界。以实际 DAA 启动链路验证设置生效，无需逐一重复完整后端联调；Mac 验证边界及 Windows 原生待实测如实记录。 |
