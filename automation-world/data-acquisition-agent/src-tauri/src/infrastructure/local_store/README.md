# Local acquisition stores v2

This adapter owns DAA-002's local SQLite schema and SQL. It is not Backend DDL or an upload protocol. Implementation and evidence state belong to the [task](../../../../plans/DAA-002-local-acquisition-loop/tasks.md).

| Store | Tables / responsibility |
| --- | --- |
| `config.sqlite` | `schema_migrations`, `instance_metadata`, content-deduplicated `source_documents`, CAS `configuration_draft`, immutable `configuration_revisions`, `active_selection`, recoverable `activation_intents` |
| `runtime.sqlite` | `schema_migrations`, `runtime_metadata`, stable `plc_sources`, immutable `configuration_contexts`, `activation_journal`, complete `collection_cycles`, self-describing `samples`, separate `sample_delivery` / `sample_references`, bounded `runtime_events` |

Both stores are initialized only together in an empty `local-acquisition-v1/`, with application IDs, user_version=2, matching instance ID and integrity checks. One missing store, incompatible schema/identity, corruption, symlink or unexpected WAL/SHM material refuses startup rather than repairing or replacing data. A profile-level OS lock prevents concurrent DAA owners, for the ordinary desktop runtime; retired headless entries never acquire it. It is not device exclusion across profiles/hosts.

Every connection verifies `page_size=4096`, incremental auto-vacuum, `journal_mode=DELETE`, `synchronous=EXTRA(3)`, `foreign_keys=ON` and `busy_timeout=1000`; `mmap_size=0`, trusted schema off. The actual default native VFS is used. SQLite handles hot journals; application code never deletes a journal or converts an unexpected WAL store. Hardware/filesystem behavior still matters.

`configuration.rs` separates prepared immutable revision, runtime explanation context, config CAS selection, loaded actors and applied acknowledgment. Recovery is idempotent and finishes selection before the engine reads active. Startup installs the recovered revision with stopped connection/collection intentions before finishing the token. Active, loaded and last-used revisions are distinct. Full runtime contexts remain after safe config-version pruning.

The serial worker admits at most four writes and one executing plus four queued short queries. A query deadline starts before enqueue; expired work does not execute. Its interrupt watchdog uses the remaining 1000 ms budget and joins before connection reuse. Timeout does not promise cancellation of blocked OS disk I/O. Four PLC actors each await a complete round commit response before reading another round, so all acquisition work in read/queue/commit is at most four rounds. Queries get a turn after at most four queued writes.

A round transaction validates immutable context and exact expected point membership, allocates one cycle ID and one sample ID per DB, writes every success/failure/null-quality fact, original timing, sorted point-ID dictionaries, complete manifest, pending delivery rows and the next source sequence. It updates last-used revision in the same commit. Source sequence is persisted as an integer and serialized as a decimal string; group filters naturally skip sequence values. Mutable ACK state is excluded from sample/manifest digests. Product code has no ACK mutator/uploader/queue-clear command; acknowledged seeds exist only in `#[cfg(test)]`.

Encoding is UTF-8 compact serde JSON with fixed struct field order, BTreeMap point dictionaries and stable UUID keys; finite REAL values retain the actual decoded f32 value represented as f64. New business calendar times use fixed Shanghai milliseconds with +08:00. SQLite generates persistence time once inside the cycle transaction; this is neither PLC event time nor an exact post-COMMIT instant. SHA-256 covers original payload bytes. History returns those bytes, not regenerated values. Metadata pages are <=100 rows. Large original configuration contexts are returned in <=64KiB UTF-8 boundary-preserving chunks through `daa_get_sample.contextOffset`; each response includes original context SHA, byte length and next offset. The GUI reconstructs and shows the original context. No cursor holds a statement or transaction between calls.

Physical admission includes runtime main/journal, config main/journal, logs, free volume space and reserves. The conservative old-page journal bound includes record/header/sector allowance; four 512KiB rounds reserve 16x B-tree/index growth plus 32MiB maintenance. Context preparation additionally budgets three times its encoded size. Configuration writes conservatively budget the old image and new payloads below 64MiB. Warning/stop/resume levels are 80/90/70%, plus 512MiB volume headroom and reserves. No `max_page_count` quota is used. A storage fault pauses acquisition until a bounded write health probe succeeds and capacity is healthy. Maintenance scans bounded batches with a forward cursor, protecting pending/incomplete/referenced cycles; eligible later cycles cannot starve behind old pending cycles. The actual 60-second worker path admits each eligible delete transaction against current physical/free-space facts, the complete old-page journal bound, four in-flight rounds, maintenance and system reserves. It re-reads the budget after cleanup before a separate incremental-vacuum transaction (64 pages); inadequate budget defers work. At most eight candidate cycles are scanned in one batch. Rollback/drop releases failed or busy transactions. Private cfg(test) cases cover overlapping references/incomplete cycles, both budget boundaries, real file-size-limit I/O failure and valid maintenance hot-journal SIGKILL/reopen; those hooks and ACK seeds are absent from product/validation builds. Events retain 500 rows and file logs rotate within 32MiB. One shared Arc/rotation mutex connects the engine and serial worker to the same profile logs; maintenance failures/deferments carry stable event/process/resource/result/error_code in bounded product JSONL and stdout, without recursively submitting a storage job. Log persistence failure emits local_log_failed/unknown_interval and latches log_io_unknown_interval until repair and restart. New storage writes and acquisition intentions stop, while read-only history/config/capacity, explicit Stop/disconnect and normal shutdown remain available; snapshot PLC errors and the log query expose the fault. These records are diagnostics, not a substitute for ledger persistence.

## SQLite 3.46.0 applicability

The approved fixed bundled dependency is rusqlite 0.32.1 / libsqlite3-sys 0.30.1. SQLite source ID is `2024-05-23 13:25:27 96c92aba00c8375bc32fafcdf12429c58bd8aabfcadab6683e35bbb9cdebf19e`. This version does not contain every later correction.

- The [WAL-reset defect](https://sqlite.org/wal.html#the_wal_reset_bug) remains unfixed here; DELETE and refusal of WAL/SHM remove its WAL precondition.
- The [3.46.1 covering-index reproducer](https://sqlite.org/forum/forumpost/e60e4c295d22f8ce) uses WITHOUT ROWID/partial UNIQUE indexes and updates. Final schema uses ordinary rowid tables and ordinary full-column indexes; stable IDs are not updated. Focused tests compare covering-index results to a full scan and independent expected count, and inspect the actual plan/opcodes.
- [3.47.0 hot-journal correction](https://sqlite.org/releaselog/3_47_0.html) targets unix-dotfile; actual VFS is native unix. A product-SQL transaction with a private fixture cache-flush hook produced a valid hot journal and was SIGKILLed; Rust reopen preserved the previous complete ledger. SIGABRT activation/commit failpoints are recorded separately.
- The later UNIQUE-PK-IN query issue does not match the static `CHECK(state IN ('pending','acknowledged'))` constraint. There are no IN-subquery predicates, views, outer joins or expression/partial indexes. The [Boolean AND projection issue](https://sqlite.org/forum/forumpost/f4878de3e7dd4764) is excluded by simple WHERE predicates and aggregates without Boolean projections; focused query results are compared.
- No extensions, FTS, SQL JSON functions, WASM/OPFS, custom VFS or arbitrary user SQL are accepted. Physical metering uses metadata, never an extra database file descriptor in the owner process. Quotas do not lower max_page_count or approach the default page-count ceiling.

The task contains the dated official-source assessment, exact dependency/source provenance, known-failure outputs and narrow applicability evidence. This is not a blanket SQLite safety claim.


## Historical YAML receipt preservation

DAA-007 r2 no longer reads YAML or executes migration in ordinary bootstrap/engine. New empty v2 stores keep empty business configuration without manufacturing a receipt/ETag. Historical algorithms, mutators and boundary tests compile only under cfg(test), without a resident execution path. No DDL, migration or record-format change is added.

The private `__daa_yaml_migration_v1__` UUID row in source_documents retains canonical JSON v1 original bytes/SHA and whitelist archive/IDs, outside editable Configuration.sources. Ordinary save/import rejects the reserved prefix and source pruning preserves private records; history is neither deleted nor recoded. Explicit compatibility summary reads only SQLite, preserves historical fields and forces retryAllowed=false in its returned view. Without a receipt it reports actual not_attempted or existing_sqlite_preserved. Retry returns yaml_retry_forbidden before a storage write job, configuration mutation or file read.

## Immutable source versions in v1

Source import uses the same DDL and dual-store identities. Optional `SourceDocument.lineageId` and `Db.importBinding` (block key, lineage and UDT source-version closure) live only in configuration JSON. Missing fields decode to None and are omitted when absent; configuration/revision/history reads never save or recode existing payloads. Older deny-unknown-fields binaries may reject newly written metadata, so downgrade is a separate compatibility gate.

A configuration source ID is a PLC-scoped logical version, while `source_documents.sha256` is a globally unique physical content archive. New logical IDs/names/PLCs with exactly equal bytes reuse the original archive row without altering its id/name/diagnostics/content. Same-ID content conflicts and hash/content disagreement reject the entire transaction. Only selected target deltas are prepared; source insertions, draft and new ETag commit in one short existing-table transaction, with CAS and rollback on failure. An unchanged draft retains its original ETag. All retained versions count against source/JSON/write limits; unselected sources and private migration receipts are protected. Active/revisions/runtime contexts/samples/manifests/generation/sequence/pending/delivery/reference remain outside this import mutation.

Point `name` is the technical ASCII name; original `sourcePath` and stable ID remain separate. Optional JSON `nameMode` is absent for legacy, or pending/auto_path/auto_address/manual. Legacy reads write nothing; conversion is explicitly selected and previewed. Pending is empty and disabled until an existing address confirmation can generate it atomically. The single owner holds naming selection/preview/token, with a private paged PointNamePreviewDialog and integrated edit/offset differences. No second owner, DDL or second key exists. Plain save cannot drop/forge modes or bypass rename previews. Immutable historical JSON/receipt bytes are not rewritten; old-binary downgrade needs separate validation.

## DAA-007 empty-profile time contract

Only new empty profiles receive the complete v2 CREATE; schema_migrations records version2 and Shanghai applied_at directly. There is no legacy ALTER/UPDATE/ledger backfill. Both metadata schema versions are2 with fixed time_profile `asia-shanghai-rfc3339-ms-v1`; samples/payload/manifest are2, configuration revisions/contexts and JSON remain1, and history/raw IPC envelopes remain1. The local-acquisition-v1 directory name is only a locator.

Before locking, preflight reads the explicitly selected profile's SQLite header/WAL material, RO metadata, identities/time contract and original-file digests. RO does not use immutable or recover a hot journal; inability to read without writing rejects the profile. Only eligible v2 or empty profiles acquire the original lock and recheck before any RW open. Legacy UTC/unknown/missing/mismatched stores return time_profile_unsupported before creating locks/logs/replacement stores. A rejection after locking can leave the lock file while business stores remain unopened for writing. Ordinary SQLite recovery for eligible v2 runs only after admission.

business_time centralizes now, RFC3339 normalization, the SQLite clock expression and rolling-days retention cutoff. History normalizes bounds to the same Shanghai millisecond strings before inclusive comparison and rejects invalid/reversed intervals. Retention, configuration created_at ordering, events and receipts follow the same contract; pending/incomplete/reference protections and budgets are unchanged. History returns original UTF-8 bytes/SHA without recoding old UTC data. stdout FormatTime keeps Shanghai nanoseconds and JSONL at keeps milliseconds; rotation/locking/failure latching/levels remain. Targeted DEV checks do not establish native operation or Stage B/C acceptance.
