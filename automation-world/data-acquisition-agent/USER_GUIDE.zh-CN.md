# DAA 使用手册

[English](USER_GUIDE.md) · [简明启动](README.zh-CN.md) · [采集数据通用指南](../../docs/acquisition-data-guide.zh-CN.md)

本手册适用于包含 DAA-010 样本上报及 DAA-013 逐 PLC 绑定的源码版本，以及已采用相应来源登记合同的后端。实际环境和运行范围以各自的部署及批准为准；本手册不代表所有环境已升级，也不代表现场或生产验收。旧版本或旧后端的操作应以其实际版本为准。

```text
PLC / 模拟器 → DAA 连接和采集 → 本机完整样本 → 上报队列
                                                ↓
                        Web 采集历史 ← 后端保存及可靠回执
```

采集和上报分别控制：可以先采集、暂停后发送，也可以同时采集和发送。「工作台 → 启动设置」中的两个开关默认关闭；开启后，下次打开 DAA 时分别自动连接已启用的 PLC 并采集、逐份上报符合条件的待传样本。保存开关不会启停本次运行；手动暂停或断开只影响本次，下次启动仍按已保存开关执行。这不是系统开机或登录自启动设置。

## 1. 启动并确认目录

确认自己使用的 DAA 源码、PLC 或模拟器、后端和 Web 均在允许的环境中。使用模拟器时先确认实例的端点和已加载配置；如何建模、加载和启动见 [DS 使用手册](../device-simulator/USER_GUIDE.zh-CN.md)。只做本地采集时无需启动后端。

DAA 和 DS 使用各自独立的 profile。已有兼容配置和历史时，启动前核对每个应用实际选择的目录和 PLC 端点，继续使用原目录；切换到空目录会产生另一套配置和历史。不要删除原目录或复制 sealed profile 来制造空环境。旧 runtime2/3 能否打开按原版本准入检查，仍只提供本地采集和历史，不会自动获得新版上报；未知版本、身份或时间不符时保留完整目录并先处理提示。

源码开发时，按需手工将 DAA 目录中的 `.env.example` 复制为 `.env`，仅在该文件不存在时复制；已有文件先自行核对。可设置 `DAA_PROFILE_DIR` 为绝对字面路径，例如：

```dotenv
DAA_PROFILE_DIR=/absolute/path/to/your/daa-profile
```

非空的进程 `DAA_PROFILE_DIR` 优先于所选 `.env`；高级 `DAA_ENV_FILE` 可另选环境文件。空值表示未设置，不表示空目录；路径不展开 `~` 或环境变量。详细的启动和兼容约束见 [README](README.zh-CN.md#启动)。

在 DAA 工程目录首次按锁文件安装依赖后，正常启动：

```sh
cd automation-world/data-acquisition-agent
pnpm install --frozen-lockfile
pnpm tauri dev
```

`cd` 从仓库根目录执行。以后从 DAA 工程目录运行 `pnpm tauri dev` 即可；如果应用已用核对过的目录运行，可直接继续。启动行为取决于工作台两个已保存开关；保存和激活 PLC 配置本身不会自动开始采集。

## 2. 配置一台 PLC 并检查本地样本

下面是合成示例，不需要照搬到已有配置。可在 DS 中使用 [minimal.db](src-tauri/tests/fixtures/source-import-minimal/minimal.db) 和 [minimal.udt](src-tauri/tests/fixtures/source-import-minimal/minimal.udt)：创建 `DEV-PLC-A`，设置 `127.0.0.1:31281`、rack `0`、slot `1`；导入 `MinimalImport` 为 DB21，确认标准布局后为三个点分别设置可读初值，再加载并启动。保存草稿、保存为版本、加载、启动各是单独动作，具体步骤见 [DS 手册](../device-simulator/USER_GUIDE.zh-CN.md)。

| DB21 原路径 | 类型 | 地址 | 示例初值 |
| --- | --- | --- | --- |
| `payload.ready` | BOOL | `0.0` | `false` |
| `payload.count` | INT | `2` | `0` |
| `payload.temperature` | REAL | `4` | `12.5` |

1. 打开 DAA「PLC 配置」，添加并启用 `DEV-PLC-A`，填入同一 IPv4、端口、机架和插槽，完成编辑并「保存草稿」。已有 PLC 则先核对，不必重复添加。
2. 打开「点位与采集组配置」，选择该 PLC，在「源文件与完整结构」选择上面的 `.db` 和 `.udt`，勾选 `MinimalImport` 并填 DB 编号 `21`。预览并确认导入；展开「辅助地址推算」，先「预览标准布局偏移」，核对上表及 8 字节长度，再「确认非人工偏移」。实际 PLC 地址须按实际资料核对。
3. 在「采集组与周期」添加并启用 `G1_1000`，周期设 `1000 ms`。勾选这三个点，点该组的「将已选点启用并分配本组」。同一 PLC/DB 的启用点放在同一组。保存草稿，点「激活配置」并确认；检查配置已应用。
4. 到「工作台」对该 PLC 点「连接」，成功后点「开始采集」。短采数秒后点「暂停采集」；暂停采集与断开连接是不同操作。
5. 打开「上报与存储 → 本地历史」，按 PLC、组及时间查询，在 DB21 行点「查看样本」，核对三个点的值、质量和采集时间。若尚未保存上报绑定，这些样本为「仅本地记录」，以后绑定也不会自动进入队列。

## 3. 登记来源并配置上报

先确认目标后端已采用单表来源合同，并确认本次来源登记和上报范围。以管理员登录 Web「采集数据 → 来源配置」，为本例新增或复用来源：`sourceType=daa`，例如 `plcId=PLC-A`、`instanceId=daa-a`、`sourceGeneration=gen-a`。新来源代次应为该 PLC 未用过的值；有旧队列时先核对原身份及既有活跃登记，不要给旧样本更换代次。

一个 DAA 可采集多台 PLC；每台在后端各有一行，在 DAA 各填一套三项。不同 PLC 的 `instanceId` 可以相同或不同，但两台本机 PLC 不能绑定同一个上报 PLC ID。在已保存的来源行点「接入参数」，再点「复制参数」。这是三个标识的 JSON。`sourceType` 只用于标注和展示，不参与样本准入；`dbNumber` 是样本字段和查询条件，不属于登记的 DB 清单。当前单表后端上报按三个标识匹配，旧 r2 目标仍按其自身 DB 范围合同运行。

1. 在 DAA「上报与存储」点「上报设置」。填写「后端服务地址（含端口）」和「上报接口路径」，核对显示的完整地址；默认路径是 `/api/v1/integration/plc-facts/samples`。`127.0.0.1` 指运行 DAA 的本机。按需要设置上报周期。
2. 在「上报来源」找到 `DEV-PLC-A` 对应行，点「粘贴」，粘贴 Web 复制的 JSON，再点「填入表单」。也可手填「实例 ID」「上报用 PLC ID」「来源代次」。逐台核对，不能把两台本机 PLC 绑定到同一上报 PLC ID。
3. 确认行中显示的 DB 来自**已生效的本机采集配置**；粘贴不会修改它。三项完整后开启该行「参与上报」，点「保存设置」。不参与的 PLC 可保留绑定并关闭开关；其采集仍可继续。保存既不验证后端登记，也不自动发送。
4. 保存绑定后再产生新采样轮，才有本次绑定的可发送样本。切换开关后，符合条件的积压可能继续发送；更改目标地址、路径或身份会暂停上报，须再次核对并显式继续。

## 4. 手测一：停采后发送积压

1. 暂停采集。在「本地历史」或「上报记录 → 查看样本」记下一份**绑定后**产生的样本 ID、本机 PLC、DB、时间、点值和质量。未冻结样本的详情不能逐条显示上报身份；本机原样本中的实例、PLC 和代次不是逐条上报身份的替代。没有符合条件的样本时，先完成第 3 节绑定，连接 PLC，短暂采集并暂停，再选择新样本；不要把旧的「仅本地记录」当成待传。
2. 开始前查看「上报记录」各状态和积压。开始会逐份处理所有开启来源中符合条件的样本，可能不止一份。未冻结样本可能没有请求正文、目标或回执；已冻结或尝试的记录可在「投递详情」核对已有的请求正文、目标及回执，未收到回执时该项仍为空。已冻结的 `prepared` 且尝试次数为 0 的样本，在核对并显式继续后可使用当前新目标，正文和身份不变。已尝试但未确认的样本保留原目标；换址须按第 6 节处理。
3. 在「上报运行」点「开始 / 继续上报」。在确认框对照后端登记和获准范围，核对**当前 URL、合同以及列出的全部来源**的实例、上报 PLC、DB 和代次，包括可能发送的积压。确认框列出来源集合，并不把某一 `sampleId` 对应到某一行。无法核清目标和所有来源时，取消确认并停止；核清后才确认。等待待发送和结果待核实的状态变化；不要只看 HTTP 状态或已确认总数。
4. 在选定样本行点「投递详情」，展开只读 JSON，核对冻结请求中的上报实例、PLC、代次及 `sampleId`；再核对回执的 `instanceId`、`sampleId` 与该请求一致，`status=committed` 且 `outcome=created` 或 `duplicate`。本地原始样本中的本机实例和 PLC ID 可以不同于上报绑定，不要把二者混同。这才是该样本的可靠确认；GET 或 HTTP 200 单独出现不能代替回执。
5. 在 Web「采集数据 → 采集历史」使用冻结请求中的**上报用 PLC ID**（本例 `PLC-A`），按 DB 和覆盖采样时刻的时间范围查询，打开**同一 `sampleId`**，比较点值与质量。本机名称 `DEV-PLC-A` 或本机 PLC ID 不能替代上报 ID。最新值可能已属于另一份样本，不能代替历史对账。

预期：采集保持暂停，选定样本的回执和 Web 历史一致；其他队列状态按实际显示。找不到记录时先检查目标 URL、来源三项、参与开关、样本状态/错误、PLC/DB、时间范围和后端是否已采用；结果未知时保留原样本及目标并核对，不手工标记确认或删除样本。

## 5. 手测二：采集与上报并行

1. 在开始或继续上报的确认框，再次核对当前目标及全部可能发送的来源和积压；无法核清时停止。确认后使「上报运行」显示上报中，记下当前「已确认」数量作为基数。
2. 到「工作台」核对该 PLC 已连接；尚未连接时先点「连接」，再点「开始采集」。在采集和上报**仍同时运行时**，观察本次开始采集后产生的新样本及其上报记录，确认至少一份新样本显示「可靠提交已确认」，且「已确认」数量高于基数；记下该样本 ID。
3. 「暂停采集」，必要时等待符合条件的队列处理，再对该新样本按第 4 节核对匹配的 `committed/created` 或 `committed/duplicate` 回执和 Web 同 `sampleId` 的点值、质量。
4. 结束时点「暂停上报」，确认工作台采集已暂停；如本次不再需要 PLC 连接，再点「断开」。暂停上报阻止新的派发，已在途请求仍可能完成。

预期：上报运行期间产生的新样本可完成与停采测试相同的回执和历史核对；若不能，按第 4 节检查并保留现场状态。

## 6. 恢复与常见问题

| 现象 | 先做什么 |
| --- | --- |
| 连不上或没有新样本 | 核对 DS 是否已加载并启动、IP/端口/rack/slot，DAA 配置是否保存并激活、点位是否启用分组，再查看工作台和本地运行事件。 |
| 上报不可用或只有本地记录 | 核对当前 profile 和版本；已绑定前的本地记录不会自动补传。保留已有数据。 |
| 待发送、结果待核实或需处理 | 在「上报记录」筛选并打开「投递详情」，核对诊断以及已有的目标和原身份；未冻结项可能没有这些逐条信息。恢复网络或核清目标后按原样本继续。未知结果不是失败或成功证明。 |
| 更换上报地址 | 地址或路径变化会暂停上报；已冻结但从未尝试的 `prepared` 样本可在核对并显式继续后使用新目标，正文和身份不变。已尝试但未确认的样本保留原目标：恢复原地址，或对结果未知的样本，根据实际部署确认新旧地址指向同一逻辑 provider 和同一数据库后，在详情选择「核对同一目标并继续原样本」。不能只凭连通或 GET 结果判断。 |
| 重启后未继续 | 查看工作台两个启动开关及启动、PLC 错误，核对已激活配置、来源绑定和目标；开关关闭时手动连接并启动。 |

本机时间显示按上海时区；保留原采集时间和原始样本。历史与可靠回执各自承担不同核对作用；接口字段、错误和读取限制见[精确合同](../../contracts/published/http-api/plc-facts-v2/README.zh-CN.md)。
