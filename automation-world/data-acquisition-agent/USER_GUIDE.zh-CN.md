# DAA 使用手册

[English](USER_GUIDE.md) · [简明启动](README.zh-CN.md) · [配置 PLC 和点位](#2-配置-plc-和点位) · [Windows 操作与验证](#windows-源码启动与手动验证) · [采集数据通用指南](../../docs/acquisition-data-guide.zh-CN.md)

本手册适用于包含 DAA-010 样本上报及 DAA-013 逐 PLC 绑定的源码版本，以及已采用相应来源登记合同的后端。实际环境和运行范围以各自的部署及批准为准；本手册不代表所有环境已升级，也不代表现场或生产验收。旧版本或旧后端的操作应以其实际版本为准。

```text
PLC / 模拟器 → DAA 连接和采集 → 本机完整样本 → 上报队列
                                                ↓
                        Web 采集历史 ← 后端保存及可靠回执
```

采集和上报分别控制：可以先采集、暂停后发送，也可以同时采集和发送。「工作台 → 启动设置」中的两个开关默认关闭；开启后，下次打开 DAA 时分别自动连接已启用的 PLC 并采集、逐份上报符合条件的待传样本。保存开关不会启停本次运行；手动暂停或断开只影响本次，下次启动仍按已保存开关执行。这不是系统开机或登录自启动设置。

## 1. 启动并确认目录

确认自己使用的 DAA 源码、PLC 或模拟器、后端和 Web 均在允许的环境中。使用模拟器时先确认实例的端点和已加载配置；如何建模、加载和启动见 [DS 使用手册](../device-simulator/USER_GUIDE.zh-CN.md)。只做本地采集时无需启动后端。

DAA 和 DS 使用各自独立的 profile。已有兼容配置和历史时，启动前核对每个应用实际选择的目录和 PLC 端点，继续使用原目录；切换到空目录会产生另一套配置和历史。不要删除原目录或复制 sealed profile 来制造空环境。旧 runtime2/3 能否打开按原版本准入检查，仍只提供本地采集和历史，不会自动获得新版上报；未知版本、身份或时间不符时保留完整目录并先处理提示。

源码开发时，按需手工将 DAA 目录中的 `.env.example` 复制为 `.env`，仅在该文件不存在时复制；已有文件先自行核对。`DAA_PROFILE_DIR` 可选择相对或绝对字面路径：

```dotenv
# 二选一；相对示例位于所选配置文件所在目录下。
DAA_PROFILE_DIR=./.local/dev
# DAA_PROFILE_DIR=/absolute/path/to/your/daa-profile
```

非空进程 `DAA_PROFILE_DIR` 优先于所选文件的非空值；两者均为空或未设置时使用应用默认目录。文件值和进程值中的相对路径都以所选文件所在目录为基准，不随命令工作目录改变；默认 DAA 根 `.env` 不存在时仍以其所在目录为基准。高级 `DAA_ENV_FILE` 须选绝对路径的可读文件，无效时拒绝且不回退。不展开 `~`、变量或占位符，拒绝上级路径及已有符号链接组件。空值表示未设置，不表示空目录。

Mac 首次使用新 profile 前，在自己控制且可写的父目录中预建空根目录，初次启动期间不让其他进程移动或替换父目录及 profile；按进程值、所选配置文件及上述基准确认实际所选目录。SQLite 文件由 DAA 创建，不要手工建库。已有兼容 profile 保留原路径、配置、样本、待确认队列、回执和封存身份，不清空、复制或迁移；身份或准入异常时保留原目录并按提示处理。预建只绕开 [r5 QA2](plans/DAA-010-sample-facts-upload/checklist.md#f-r5-qa2-001-首次创建期间替换的空目录被封存为新-profile) 的自动创建特定窗口：底层竞态尚未修复，也不证明其他替换安全。本源码开发规则不证明安装版 `.env` 的发现或分发；Windows 原生验证仍待进行。详细的启动和兼容约束见 [README](README.zh-CN.md#启动)。

在 DAA 工程目录首次按锁文件安装依赖后，正常启动：

```sh
cd automation-world/data-acquisition-agent
pnpm install --frozen-lockfile
pnpm tauri dev
```

`cd` 从仓库根目录执行。以后从 DAA 工程目录运行 `pnpm tauri dev` 即可；如果应用已用核对过的目录运行，可直接继续。启动行为取决于工作台两个已保存开关；保存和激活 PLC 配置本身不会自动开始采集。

### Windows 源码启动与手动验证

以下供 Windows 10/11 x64 后续实机使用，当前尚无 Windows 原生验证结果。准备完整仓库、Git、Node.js、项目指定的 pnpm、Rust 的 Windows MSVC 工具链、Microsoft C++ Build Tools（含 Windows SDK）和 WebView2 Runtime；详见 [Tauri Windows 前置条件](https://v2.tauri.app/start/prerequisites/#windows)。

1. 确认 DAA 和 DS 分别选择各自的数据目录。已有兼容目录时核对后继续使用，不要覆盖。需要显式选择 DAA 目录时，可在 PowerShell 中设置 `$env:DAA_PROFILE_DIR = 'C:\AIIS\DAA\profile'`，将示例替换为自己的**绝对路径**；它优先于 `.env` 中的值。DS 启动和目录选择见 [DS 使用手册](../device-simulator/USER_GUIDE.zh-CN.md)。
2. 在同一 PowerShell 的仓库根目录依次运行：

   ```powershell
   cd .\automation-world\data-acquisition-agent
   pnpm install --frozen-lockfile
   pnpm tauri dev
   ```

3. 按本手册第 2–3 节配置模拟 PLC、采集及上报来源，再按第 4–5 节分别检查停采上报和采集、上报并行；对选定的同一 `sampleId` 核对可靠回执和 Web 历史。已有配置时先核对，不必重新创建。
4. 需要记录首次初始化、关闭重开、独占锁及异常恢复结果时，使用 [Windows 原生验证记录单](WINDOWS_NATIVE_VALIDATION.zh-CN.md)。其中首次自动建库验证要求所选测试 profile **预先不存在**；日常使用已存在目录与该项验证目的不同。未实际执行的项目记为未测。

## 2. 配置 PLC 和点位

| 手头的资料或目标 | 按这个顺序操作 |
| --- | --- |
| 有 DS 或 DAA 导出的 PLC JSON | 直接[导入 PLC JSON](#24-导入-plc-json)，一步创建 PLC 和点位的草稿。 |
| 有 TIA 的 `.db` / `.udt` 文件 | [添加或选中 PLC](#21-手工添加-plc) → [导入点位并确认地址、DB 长度](#22-从-db--udt-导入点位) → [按需编辑名称](#23-编辑名称分组及启用)。 |
| 只想传配置给另一端 | [导出 PLC JSON](#25-导出-plc-json)。选择「已保存草稿」即可导出新配置。 |
| 准备实际采集 | [分组并启用](#23-编辑名称分组及启用) → [保存草稿 → 激活配置 → 连接 → 开始采集](#26-需要采集时才激活并启动)。 |

DAA 通过 DB / UDT 或 PLC JSON 生成点位。要从零手工建 DB 和点位，请在 [DS](../device-simulator/USER_GUIDE.zh-CN.md) 建好，导出 PLC JSON 再导入 DAA。

### 2.1 手工添加 PLC

1. 打开「配置中心 → PLC 配置」。已有目标 PLC 时复用该行。新建时点「添加 PLC」，最多 4 台，端点必须唯一。
2. 填「名称」「IPv4 地址」「端口」「机架」「插槽」，与 PLC 或 DS 的实际监听参数一致。同机连接 DS 可用 `127.0.0.1`。新建时「启用」默认关闭。
3. 点弹窗「保存草稿」。确认 PLC 出现在列表，再点「配置点位」，在「PLC」下拉框核对当前对象。接着导入点位。

### 2.2 从 DB / UDT 导入点位

1. 在「点位与采集组配置」选中目标 PLC，先保存未保存的草稿。展开「源文件与完整结构 → 选择源文件」，同时选取 `.db` 及其引用的 `.udt`。含 JSON 目录 DB 的 PLC 禁用此入口。
2. 逐页只勾选要导入的 DB，填实际「DB 编号」。新增 DB 时把「已有目标（显式更新）」留空。更新已有 DB 时显式选目标。UDT 只作依赖，无需编号。
3. 点「预览导入差异」，核对 DB、结构、点位路径、候选技术名和诊断。确认后点「确认导入并保存」。点表出现新点位后，逐个 DB 执行下面的地址和长度核对。
4. **确认地址。**在「DB」中选一块，展开「辅助地址推算 → 预览标准布局偏移」，对照实际 PLC 资料核对字节、位、候选技术名和计算长度，再点「确认非人工偏移」。推算只适用于完整、明确非优化的标准布局。含 STRING 或未知类型、优化或结构不完整的 DB 无法使用该推算。需要手工确认时，在点位行点「编辑」，填写「字节偏移」、BOOL 的「位偏移」和「确认依据」，核对后打开「地址已确认」，检查名称预览并点「保存草稿」。以后改地址时重新确认，已有人工地址不会被推算覆盖。
5. **核对 DB 长度。**普通来源新建 DB 的 `65536` 字节是初始值。只有全部点符合并参与非人工偏移确认，长度才自动更新为理论值。若需修正，点「源文件与完整结构 → 查看完整结构」，展开对应 DB，填实际「DB 长度（字节）」，关弹窗后点页面顶部「保存草稿」。

本机示例可用 [minimal.db](src-tauri/tests/fixtures/source-import-minimal/minimal.db) 和 [minimal.udt](src-tauri/tests/fixtures/source-import-minimal/minimal.udt)。将 `MinimalImport` 作为 DB21，核对 `payload.ready` BOOL `0.0`、`payload.count` INT `2`、`payload.temperature` REAL `4` 和 8 字节 DB 长度。

### 2.3 编辑名称、分组及启用

1. **检查点位。**选对 PLC 和 DB，核对「技术名称」、类型和地址。点「编辑」，按需填写「中文显示名称」「英文显示名称」和「注释」，核对名称预览后点弹窗「保存草稿」。「保存草稿并编辑」会先保存当前草稿。显示名每种语言上限 256 UTF-8 字节，未填保持空白。顶栏切换显示语言。当前 v2 上报使用技术名，显示名仅用于界面及配置交换。
2. **建组并启用要采集的点。**展开「采集组与周期 → 添加采集组」，填名称和周期，打开组的「启用」。在点表勾选目标点，回到对应组点「将已选点启用并分配本组」。同一 PLC / DB 的启用点放在同一组。勾选跨页和筛选保留，操作前核对已选数量。
3. **保存并启用 PLC。**点顶部「保存草稿」。回「PLC 配置 → 编辑」，打开目标 PLC 的「启用」，点弹窗「保存草稿」。确认所需点已启用、组名正确，页面显示「草稿已保存」。仅准备配置时到此即可，实际采集请继续 2.6。

要停用点位，点表勾选后使用「禁用已选点并取消分组」，再点顶部「保存草稿」。在单点编辑器关闭「启用」会保留它的分组。

### 2.4 导入 PLC JSON

1. 保存或取消当前编辑，再打开「PLC 配置 → 导入 PLC JSON → 选择 JSON 文件」。选择 DS 或 DAA 导出的单 PLC 文件，由导入流程创建 PLC。
2. 在「核对采集客户端目标」检查 IPv4、端口、机架和插槽，确保 DAA 能访问。改过目标后点「重新预览」。回环地址只适合同机连接。DAA 会拒绝不支持的非默认 TSAP。
3. 核对预览中的全部 DB 和点位，包括停用项、技术名、类型、地址、双语名称和描述。若提示同源仅存在于历史，按需勾选「作为新的本机实例导入」，新实例使用独立的本机身份。
4. 勾选「我已核对目标地址和完整点位，确认将描述写入新点注释」，点击「确认新建并保存草稿」。成功后去「点位与采集组配置」核对新 PLC 和点数。新 PLC、点位默认停用且未分组。只交换文件时可直接结束或按 2.5 导出。要采集再做 2.3 和 2.6。

JSON 导入后可改双语显示名、注释、分组及启用。技术名、类型、地址和点集由目录固定，该 PLC 的 DB / UDT 追加入口禁用。

**同源或端点冲突：**当前草稿、活动或运行配置中的同源 PLC 会阻止导入。端点重复时先核对目标。确需移除同源 PLC 时，先确认影响。仍在活动或运行中时先停采、断连。点该 PLC 的「编辑 → 移除 → 确认」，再点顶部「保存草稿」。仅存在于草稿时可重试。仍存在于活动或运行配置时，先显式激活移除后的配置，再重试。历史新实例不会继承旧样本、上报绑定、队列或回执。

文件变化后重新选择并预览。结果未知时先重新读取草稿、核对来源，再决定是否重试。预览中的来源配置摘要由导出方声明，实际设备布局须另行核对。

### 2.5 导出 PLC JSON

1. 保存要交接的编辑，打开「PLC 配置 → 导出 PLC JSON」。选择「已保存草稿」或「活动版本」，核对所选版本。文件不含界面未保存的编辑。
2. 勾选要导出的 PLC。默认取 PLC 名，缺少 `.json` 后缀时自动补上（后缀不区分大小写）。可单独改名，使用合法且不重复的文件名（保留 `.json`，同批不以大小写区分）。点「预览所选 PLC」，核对每台的客户端目标和所有 DB、点位。修改选项或文件名后重新预览。
3. 勾选「我已核对每台 PLC 的客户端连接目标与完整点位」，依次点「选择导出目录」和「导出」。看顶部结果和每行的「已导出」。同名文件保留，可改名或换目录。结果未知时先检查目录。
4. 在 DS「实例 → 导入 PLC JSON」选择文件，接着核对监听目标、布局和名称。详见 [DS 手册](../device-simulator/USER_GUIDE.zh-CN.md)。

### 2.6 需要采集时才激活并启动

1. 核对目标端点、点地址、采集组和 PLC / 组 / 点启用状态。在配置页顶部点「保存草稿 → 激活配置」，确认并检查「已应用」。激活若不可用，先处理配置栏列出的问题。
2. 在「工作台」找到目标 PLC，点「连接」，等连接成功再点「开始采集」。使用本机 DS 时，先在 DS 加载所需版本并启动实例。
3. 到「上报与存储 → 本地历史」按 PLC、组和时间查询，点「查看样本」核对值、质量和时间。结束时先「暂停采集」，按需「断开」。

只采集时可停在本节。未绑定时生成的样本为「仅本地记录」，以后绑定也不会自动进队列。需要上报再按第 3–5 节操作。

测试结束，仅处理确认属于本次的测试对象和导出文件。涉及活动版本或历史引用的对象先保留。原生验证记录见 [DAA-019](plans/DAA-019-plc-json-bidirectional/checklist.md) 和 [DAA-017](plans/DAA-017-plc-json-import/tasks.md)。

## 3. 登记来源并配置上报

先确认目标后端已采用单表来源合同，并确认本次来源登记和上报范围。以管理员登录 Web「采集数据 → 来源配置」，为本例新增或复用来源：`sourceType=daa`，例如 `plcId=PLC-A`、`instanceId=daa-a`、`sourceGeneration=gen-a`。新来源代次应为该 PLC 未用过的值；有旧队列时先核对原身份及既有活跃登记，不要给旧样本更换代次。

一个 DAA 可采集多台 PLC；每台在后端各有一行，在 DAA 各填一套三项。不同 PLC 的 `instanceId` 可以相同或不同，但两台本机 PLC 不能绑定同一个上报 PLC ID。在已保存的来源行点「接入参数」，再点「复制参数」。这是三个标识的 JSON。`sourceType` 只用于标注和展示，不参与样本准入；`dbNumber` 是样本字段和查询条件，不属于登记的 DB 清单。当前单表后端上报按三个标识匹配，旧 r2 目标仍按其自身 DB 范围合同运行。

1. 在 DAA「上报与存储」点「上报设置」。填写「后端服务地址（含端口）」和「上报接口路径」，核对显示的完整地址；默认路径是 `/api/v1/integration/plc-facts/samples`。`127.0.0.1` 指运行 DAA 的本机。按需要设置上报周期。
2. 在「上报来源」找到 `DEV-PLC-A` 对应行，点「粘贴」，粘贴 Web 复制的 JSON，再点「填入表单」。也可手填「实例 ID」「上报用 PLC ID」「来源代次」。逐台核对，不能把两台本机 PLC 绑定到同一上报 PLC ID。
3. 确认行中显示的 DB 来自**已生效的本机采集配置**；粘贴不会修改它。三项完整后开启该行「参与上报」，点「保存设置」。不参与的 PLC 可保留绑定并关闭开关；其采集仍可继续。保存既不验证后端登记，也不自动发送。
4. 保存绑定后再产生新采样轮，才有本次绑定的可发送样本。切换开关后，符合条件的积压可能继续发送；更改目标地址、路径或身份会暂停上报，须再次核对并显式继续。

## 4. 手测一：停采后发送积压

1. 暂停采集。在「本地历史」或「上报记录 → 查看样本」记下一份**绑定后**产生的样本 ID、本机 PLC、DB、时间、点值和质量。未冻结样本的详情不能逐条显示上报身份；本机原样本中的实例、PLC 和代次不是逐条上报身份的替代。没有符合条件的样本时，先完成第 3 节绑定，连接 PLC，短暂采集并暂停，再选择新样本；不要把旧的「仅本地记录」当成待传。
2. 开始前查看「上报记录」各状态和积压。开始会逐份处理所有开启来源中符合条件的样本，可能不止一份。未冻结样本可能没有请求正文、目标或回执；已冻结或尝试的记录可在「投递详情」核对已有的请求正文、目标及回执，未收到回执时该项仍为空。已冻结的 `prepared` 且尝试次数为 0 的样本，在核对并显式继续后可使用当前新目标，正文和身份不变。已尝试但未确认的样本保留原目标；换址须按第 6 节处理。
3. 在「上报运行」点「启动上报」。在确认框对照后端登记和获准范围，核对**当前 URL、合同以及列出的全部来源**的实例、上报 PLC、DB 和代次，包括可能发送的积压。确认框列出来源集合，并不把某一 `sampleId` 对应到某一行。无法核清目标和所有来源时，取消确认并停止；核清后才确认。等待待发送和结果待核实的状态变化；不要只看 HTTP 状态或已确认总数。
4. 在选定样本行点「投递详情」，展开只读 JSON，核对冻结请求中的上报实例、PLC、代次及 `sampleId`；再核对回执的 `instanceId`、`sampleId` 与该请求一致，`status=committed` 且 `outcome=created` 或 `duplicate`。本地原始样本中的本机实例和 PLC ID 可以不同于上报绑定，不要把二者混同。这才是该样本的可靠确认；GET 或 HTTP 200 单独出现不能代替回执。
5. 在 Web「采集数据 → 采集历史」使用冻结请求中的**上报用 PLC ID**（本例 `PLC-A`），按 DB 和覆盖采样时刻的时间范围查询，打开**同一 `sampleId`**，比较点值与质量。本机名称 `DEV-PLC-A` 或本机 PLC ID 不能替代上报 ID。最新值可能已属于另一份样本，不能代替历史对账。

预期：采集保持暂停，选定样本的回执和 Web 历史一致；其他队列状态按实际显示。找不到记录时先检查目标 URL、来源三项、参与开关、样本状态/错误、PLC/DB、时间范围和后端是否已采用；结果未知时保留原样本及目标并核对，不手工标记确认或删除样本。

## 5. 手测二：采集与上报并行

1. 在开始或继续上报的确认框，再次核对当前目标及全部可能发送的来源和积压；无法核清时停止。确认后使「上报运行」显示上报中，记下当前「已确认」数量作为基数。
2. 到「工作台」核对该 PLC 已连接；尚未连接时先点「连接」，再点「开始采集」。在采集和上报**仍同时运行时**，观察本次开始采集后产生的新样本及其上报记录，确认至少一份新样本显示「可靠提交已确认」，且「已确认」数量高于基数；记下该样本 ID。
3. 「暂停采集」，必要时等待符合条件的队列处理，再对该新样本按第 4 节核对匹配的 `committed/created` 或 `committed/duplicate` 回执和 Web 同 `sampleId` 的点值、质量。
4. 结束时点「暂停上报」，确认工作台采集已暂停；如本次不再需要 PLC 连接，再点「断开」。暂停上报阻止新的派发，已在途请求仍可能完成。

预期：上报运行期间产生的新样本可完成与停采测试相同的回执和历史核对；若不能，按第 4 节检查并保留现场状态。

## 6. 恢复与常见问题

| 现象 | 先做什么 |
| --- | --- |
| 连不上或没有新样本 | 核对 DS 是否已加载并启动、IP/端口/rack/slot，DAA 配置是否保存并激活、点位是否启用分组，再查看工作台和本地运行事件。 |
| 上报不可用或只有本地记录 | 核对当前 profile 和版本；已绑定前的本地记录不会自动补传。保留已有数据。 |
| 待发送、结果待核实或需处理 | 在「上报记录」筛选并打开「投递详情」，核对诊断以及已有的目标和原身份；未冻结项可能没有这些逐条信息。恢复网络或核清目标后按原样本继续。未知结果不是失败或成功证明。 |
| 更换上报地址 | 地址或路径变化会暂停上报；已冻结但从未尝试的 `prepared` 样本可在核对并显式继续后使用新目标，正文和身份不变。已尝试但未确认的样本保留原目标：恢复原地址，或对结果未知的样本，根据实际部署确认新旧地址指向同一逻辑 provider 和同一数据库后，在详情选择「核对同一目标并继续原样本」。不能只凭连通或 GET 结果判断。 |
| 重启后未继续 | 查看工作台两个启动开关及启动、PLC 错误，核对已激活配置、来源绑定和目标；开关关闭时手动连接并启动。 |

本机时间显示按上海时区；保留原采集时间和原始样本。历史与可靠回执各自承担不同核对作用；接口字段、错误和读取限制见[精确合同](../../contracts/published/http-api/plc-facts-v2/README.zh-CN.md)。
