# Device Simulator

An independent S7 PLC simulator derived from the applicable DAA desktop assembly. The six-page Tauri/Vue application and the test host use the same Rust runtime. Rust owns configuration, the DB images, all writes, rules and control; the limited Snap7 adapter owns protocol, socket IO and native worker lifecycle. DAA, SMA and Backend do not have to run.

[User guide](USER_GUIDE.md) · [Build and run](BUILD.md) · [Plan](PLAN.md) · [Runtime](runtime/README.md) · [Native adapter](native/README.md) · [Tests](tests/README.md) · [Detailed design](../../docs/AIIS_DS_Detailed_Design.md)

The product starts with an empty configuration and stopped instances. Configure UUID instances and DBs, import explicitly selected DB/UDT declarations or create manual points, confirm addresses/names/initial values/policies, save an immutable revision, then apply it while stopped. Start is a separate action. Online values, connections and bounded logs show actual runtime facts; a browser preview cannot perform desktop operations.

All 13 page/preview tables share a thin Element Plus wrapper with DAA/CU themes and density. Regular columns resize by dragging and remember widths locally by stable table/field identities; every table offers Reset column widths. Preferences do not enter business SQLite or saved revisions and do not alter filters, selection, pagination or permissions. Long text uses overflow help, scrolling stays inside tables, and narrow containers unfreeze the right side to avoid covering data. See [guide §1.1](USER_GUIDE.md#11-column-widths-and-viewing-in-every-table).

Each profile has an independent `device-simulator-v1/config.sqlite`, an OS profile lock and a persistent WebKit data-store UUID. The default is Tauri's DS application local-data directory; optional `DS_PROFILE_DIR` accepts an explicit absolute path. Unknown, corrupt, incompatible or read-only databases are rejected and retained. Runtime values, connections and running intent are not stored: reopening loads the selected revision, initializes its values and remains stopped. Save, selected and loaded versions are separate.

For source development, the Owner may manually copy this directory's `.env.example` to `automation-world/device-simulator/.env` and optionally fill only `DS_PROFILE_DIR`; preserve/review an existing file. Precedence is nonblank process > own .env nonblank value > Tauri's original default. A blank key means unset, not an empty directory. Paths are absolute literals, without `~`/variable expansion, parent traversal or existing symlinks. Invalid selection rejects before lock/database/logs without fallback. Simple KEY=VALUE removes one paired quote layer and first duplicate wins; no parent/other-app .env search or shell execution occurs. Once configured, start with only `pnpm tauri dev`; Tauri retains `native-s7`. UI + SQLite own instances/points/policies; save, stopped load and Workbench start remain separate, and startup/reopen remain stopped. Dev/build do not automatically isolate data; installed-package .env discovery/distribution is outside this contract. The new DAA-007 r2 bootstrap contract awaits that task's independent verification, outside prior DS acceptance.

Calendar displays use Asia/Shanghai (UTC+08:00) to seconds, independent of the computer's time zone, retaining original milliseconds. Online-value `updatedAt` records initialization or the last successful commit while `updatedNs` remains monotonic; refreshes and unchanged rule values do not advance it. New log events carry an RFC3339 `timestamp` with `+08:00`; `monotonic_ns` remains a separate ordering/duration counter. Legacy logs without calendar time are labelled accordingly, without inferred dates. Revision displays use real sequence summaries and aligned/pending status; question-mark help retains full identities, all three states and explanations. Existing SQLite `*_utc` fields and revision payloads retain their legacy UTC format and are converted once for display; this correction performs no database/schema/history migration. New native time fields take effect after the development process rebuilds/restarts.
