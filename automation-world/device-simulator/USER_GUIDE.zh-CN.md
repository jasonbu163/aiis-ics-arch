# DS 设备模拟器操作手册

[English](USER_GUIDE.md) · [工程入口](README.zh-CN.md) · [构建说明](BUILD.zh-CN.md) · [DS-001 开发记录](plans/DS-001-policy-table-and-usability/tasks.md)

## 快速操作流程

1. **启动**：在 `automation-world/device-simulator` 目录执行 `pnpm tauri dev`，沿用现有数据目录。
2. **创建实例**：配置中心 → 实例 → **创建实例**，填写名称和端口 → **完成编辑 → 保存草稿**。
3. **建立点位**：DB 点位 → 选实例 → 新增 DB、手工点，或导入 DB/UDT；完成地址和命名确认。
4. **设置行为**：模拟与读写策略 → 选点 **编辑策略**，填写模式、初值和读写权限 → **完成编辑 → 保存草稿并确认所选初值/策略**。
5. **保存版本**：顶部 **保存草稿 → 保存为版本**，核对弹窗 → **确认保存为版本**。
6. **应用配置**：目标实例先停止；实例 → 配置版本与加载 → 选目标实例 → 正确版本行 **预览加载** → 核对清单、勾确认 → **确认加载并保持停止**。
7. **开始模拟**：工作台 → **启动**；在线值页查看点位、运行值和实际已加载版本。

只改草稿不会改变运行配置；保存版本后还需加载，加载后还需启动。已有实例从未完成处接续，不必重复创建。

## 1. 准备与动作边界

按[构建说明](BUILD.zh-CN.md)准备既定工具链。已安装依赖可直接启动；只有缺失依赖时才用项目声明版本执行 `pnpm install --frozen-lockfile`，不改锁文件。正常使用默认数据目录，不要求另建家目录。若终端当前位于仓库根目录，执行：

```sh
cd automation-world/device-simulator
pnpm tauri dev
```

已在 `automation-world/device-simulator` 工程目录时，只执行 `pnpm tauri dev` 即可。仅 `pnpm dev` 是浏览器前端，没有桌面 bridge，不能完成保存、导入或启停。

**默认数据与既有配置。** 进程和本应用根.env都没有非空 `DS_PROFILE_DIR` 时使用 Tauri 的 DS 应用本地数据目录；在“日志与存储”核对实际配置库路径。配置保存到该目录下的 `device-simulator-v1/config.sqlite`，日志和 WebKit 持久 store 也由相应 profile 管理。正常重开复用该目录，不清库。全新目录才预期空配置；已有默认目录可能显示原实例和保存历史，重开仍按所选版本初始化并保持停止。先在“实例”核对现有对象：若已有 `PLC_Test`，检查端点及 DB31/71/88，按已完成位置接续，不重建同名实例、不覆盖其它配置；教程所用名称或 DB 号已被其它用途占用时，先辨明归属再决定示例对象，不删除数据来让教程从零开始。

**dev 与 build 不会自动分离数据。** 开发启动和构建出的桌面程序使用同一个应用 identifier `com.aiis.aw.devicesimulator`，未显式改变 profile 时，在同一用户下会使用相同默认目录、复用实例和版本历史。`pnpm tauri build` 编译本身不清除现有外置 SQLite，也不会把该库自动装进程序；“构建成功”不表示得到空白数据环境。同一 profile 不能被两个程序同时占用，须正常关闭持锁实例后切换。

**可选：一次配置源码开发profile。** 在本工程根目录，手工复制 `.env.example` 为 `.env`；已有文件先检查，只编辑自己的活动键，不覆盖。可填 `DS_PROFILE_DIR` 为自己拥有的绝对目录；留空使用原默认。进程非空值 > 自身.env非空值 > 默认，重复键首项生效。仅简单KEY=VALUE，允许一层成对引号，不展开`~`、`$VAR`/`${VAR}`或执行shell，不扫描父目录/其他应用。相对路径、父目录穿越、symlink、非UTF-8/不可读.env会在锁/开库/日志前拒绝，不退回默认建旁库。安装包.env发现/分发不在本次承诺内。

如曾在当前终端export `DS_PROFILE_DIR`，它会覆盖.env；Owner一次核对并按需`unset DS_PROFILE_DIR`。之后每次仅 `pnpm tauri dev`，正常重开复用同一profile。不要source整份.env。一个profile键只选存储根，PLC/点位/策略由UI+SQLite管理，运行启停走工作台；保存/加载不自动启动，connected/运行意图不恢复。不要删除默认库来制造空白教程。DAA-007联调仅沿用[联调手册](../data-acquisition-agent/JOINT_TEST_GUIDE.zh-CN.md)指定的原Owner合成profile，不复制DEV测试库。

若提示 pnpm store 不匹配，核对 `pnpm store path` 与本工程 `node_modules/.modules.yaml` 的 `storeDir`；使用既定 pnpm 重装本工程锁定依赖，不能把旧任务临时 store 当产品依赖。端口占用时查占用事实并由所有者处理，不结束未知进程。`profile_in_use` 应正常关闭持锁的自有实例，不能删除锁抢占。

| 页面 | 用途 |
| --- | --- |
| 工作台 | 查看运行状态；启动、暂停/恢复规则、停止、重置 |
| 配置中心 → 实例 | 新建实例；核对版本，预览并停机加载 |
| 配置中心 → DB 点位 | DB/点结构、源导入、完整地址与命名确认 |
| 配置中心 → 模拟与读写策略 | 当前草稿的策略表格、单点/批量覆盖与上层继承 |
| 在线值 | 实际 loaded 版本的地址、类型、值及普通/维护写入 |
| 日志与存储 | 错误、配置库路径、有界日志及丢失计数 |

五个动作分别执行：**完成编辑**只把弹窗内容接回当前编辑稿；**保存草稿**持久更新SQLite中的同一份草稿，正常重开保留且不增加版本；**保存为版本**明确创建整个工作区的不可变快照，与最新版本内容相同则不重复生成；列表行**预览加载**并确认只替换目标实例的内存版本且保持停止；**启动**才打开监听并推进规则。导入、地址/命名、初值/策略确认及保存草稿后关闭也只更新草稿，不隐式发布、加载或启动。

| 你看到的内容 | 含义与查看位置 |
| --- | --- |
| 当前草稿 | 配置中心正在编辑的实例、DB、点位和策略；保存草稿后保留，仍可继续修改 |
| 最新版本 | 最近一次明确保存的整个工作区快照；编号如 v15，不代表每个实例都已使用它 |
| 实例已选 | 该实例持久记录的版本，正常重开时用它初始化；版本旁问号可查看 |
| 实际已加载 | 当前内存正在使用的版本；工作台、在线值及版本使用状态可核对 |
| 回退保留 | 真正换版时保留的原已选版本；只是保留记录，不代表正在使用，也不保证旧版本校验通过 |

切换版本只加载目标实例，不把历史快照回填到当前草稿，也不同时切换其它实例。配置中心看草稿，在线值看实际已加载配置；两者允许暂时不同。

字段旁的问号可用鼠标悬停或键盘聚焦查看解释。版本、更新时间、日志时间和在线值操作的说明收在这里；确认弹窗中的风险及结果未知提示仍须阅读。版本、在线值和日志的日历时间均显示上海时间到秒，例如 `2026-10-23 11:39:15`；原始毫秒不删除，也不四舍五入到下一秒。

### 1.1 所有表格的列宽与查看操作

工作台、实例、配置版本、DB点位、策略、在线值、连接、日志，以及命名/地址/导入/加载/批量/版本清理预览中的表格共用相同组件，原有筛选、选择范围及分页方式保持。

1. 例如进入 **配置中心 → DB点位**，选已有PLC和DB。把鼠标移到“名称”表头右边界，看到左右调整光标后拖动，松开即可保留列宽。普通数据列可拖拽且有最小宽度；选择框、操作等功能列固定宽度。
2. 长文本默认单行省略，悬停可看完整内容；原始值和输入框内容不因显示截断而改变。输入控件、确认状态与批量前后差异允许按内容展开。宽表在表格内部横向滚动，长表内部纵向滚动且表头保留；桌面操作列固定右侧，窄表格为避免遮住数据取消右侧冻结，向右滚动即可查看操作。
3. 在同一表翻页、筛选、刷新或切到其它页面再回来，列宽应保留。切换中英文后同一字段仍使用原宽度；不同表格分别记忆，不会因字段同名互相覆盖。原有跨页勾选规则仍按各页面说明执行。
4. 每张表右上角都有 **恢复默认列宽**。点击后只清除此表的列宽偏好，不清空筛选、勾选、当前页、编辑值或PLC配置，不产生候选版本、不改变运行值。另一个表格的列宽保持。
5. 列宽保存在本机当前WebView的`localStorage`，不保存到DS业务SQLite或配置版本。同一启动入口和profile正常重开可恢复；不同电脑、开发/安装包的不同页面源或不同WebView数据目录不承诺共享。清理应用页面数据可能清除列宽偏好。
6. 新增列使用默认宽度；删除字段、变成固定功能列或不再满足最小宽度的旧偏好会被忽略并回退默认。如果看到“本机偏好存储不可用”，拖拽或恢复仍能在当前页面生效，但重开后的保存不作保证；不用通过删除业务库处理。

## 2. 手工 DB31：从创建到保存、加载与运行

首次使用依次做2.1–2.6即可；固定值和批量示例在第4节，可按需再做。下面每次“完成编辑”之后仍需保存草稿，所有启用 DB 都要完成地址、名称、初值和策略确认。

### 2.1 创建实例

1. 页面：**配置中心 → 实例**。先核现有实例；没有 `PLC_Test` 时点击该页 **创建实例**，已有时核对下列字段并接续DB步骤，不重复新建。
2. 填写：名称 `PLC_Test`；IPv4 回环 `127.0.0.1`；端口 `30102`；rack `0` / slot `1`；Calling TSAP 十进制 `256`；已建立连接上限 `16`、握手上限 `4`。若已有其它实例使用 `127.0.0.1:30102`，保留该实例不改，新建教程 PLC_Test 改用 `30103`，并确认这个端口可用；后续教程端点均以本次实际填写端口为准。没有占用时仍用 `30102`。
3. 点击 **完成编辑**，再点顶部 **保存草稿**。
4. 预期：表中有 PLC_Test、所填端点（`127.0.0.1:30102`，或避让后的 `127.0.0.1:30103`）、`16/4`；显示“草稿已保存”，版本数量不变，首次还没有版本。未配置 DB 的提示留待下一步，尚未加载时工作台可能没有运行行。
5. 恢复：保存失败保留当前草稿，记录提示，不重复创建同名实例；ETag 冲突先抄下编辑意图再明确重新读取。

### 2.2 新建 DB 与三点

1. 页面：**DB 点位**。选择 PLC_Test；DB31不存在时点 **新增 DB**。已有本教程DB31时先核长度和三点，从未完成步骤接续，不再新增同号DB。
2. 新DB会被自动选中；直接在下方表单填 DB 名 `Manual_Demo`、DB 号 `31`、DB 长度 `8` 字节，并保持启用。DB字段直接进入当前草稿，没有单独的DB提交弹窗。
3. 逐次点 **新增手工点**，填下表，每次 **完成编辑**。点名称是 ASCII，显示名可自由填写；每点启用。

| 名称 | 类型 | 字节 | 位 | 人工理由示例 |
| --- | --- | --- | --- | --- |
| `Run_Bool` | BOOL | `0` | `0` | `合成DB31，仅映射DBX0.0` |
| `Setpoint_Int` | INT | `2` | 不显示 | `合成DB31，占字节2和3` |
| `Temperature_Real` | REAL | `4` | 不显示 | `合成DB31，占字节4至7` |

4. 核三行地址 `0.0` / `2` / `4`、长度8；**保存草稿**。操作列编辑/删除之间应有8px间距，窄窗口允许换行而不覆盖。
5. 恢复：缺名、缺理由或越界先取消/修正当前弹窗；长度8最高覆盖字节7，不能只留默认长度1。未映射空隙不因此成为可写点。

### 2.3 完整人工地址与命名

1. 仍在 DB31，已保存后点 **确认完整人工地址**。填整 DB 理由：`合成DB31：BOOL0.0，INT字节2至3，REAL字节4至7，长度8，无重叠。`
2. 点 **预览**。预期弹窗显示目标 DB31 / Manual_Demo、长度8、整DB理由及三行类型/地址/逐点人工理由；没有空的命名表。逐项核对后 **确认**。
3. 点表勾表头，选中这三个点 → **预览所选点命名**。此处预期有真实命名行；核对原三名保留 → **确认**。
4. 恢复：预览不符点 **取消**，回点表修正并保存，再重新预览；token/ETag过期不能复用。点表表头只选当前页，跨页可累计；切 DB/PLC清空。它和下一节策略表“全筛选全页”不同。点表“待确认”指初值/策略，不等于地址未确认。

### 2.4 设置三个点的模式、初值和权限

1. 页面：**模拟与读写策略**。选 PLC_Test，DB筛选选 Manual_Demo。主表只读显示 DB/点/类型/地址、有效模式、初值、唯一写方、规则摘要、初值/策略确认状态；**权限与来源**展开逐属性值及来自默认/实例/DB/region/点的层级。它是当前草稿预览，不是旧loaded值或服务端确认。
2. 对 Run_Bool 点 **编辑策略**。模式 **布尔翻转**；核联动 owner=持续规则、三个写权限禁止。客户端读继承默认允许；勾 DS初值 **显式覆盖**，正常输入 `false`；半周期 `1500`，其它通用参数保留。核对弹窗前后值 → **完成编辑**。
3. 对 Setpoint_Int 编辑：模式 **保持**；之后 owner选 **界面**；界面普通写 **允许**，客户端写和维护写 **禁止**，客户端读取保持允许。勾初值覆盖，输入 `7`，按 Tab 后核对仍为7 → **完成编辑**。
4. 对 Temperature_Real 编辑：模式 **斜坡**；owner规则/其它写禁止，客户端读取保持允许；初值覆盖 `20.5`；min `0`、max `100`、period `10000`、phase `0`。核对后 **完成编辑**。
5. 核每次模式切换的 owner、写权限和完整规则联动；它们在副本内，**取消**应全部不进草稿。数字 `0`与BOOL `false`均为合法显式值，不能与“继承”混同。
6. 只勾三点，点 **保存草稿并确认所选初值/策略**。此按钮只确认选中点，不确认结构地址，不自动确认其它DB。预期三点初值为 `false/7/20.5`，初值和策略状态均已确认；BOOL、REAL由规则生成，INT由界面普通写入。
7. 恢复：输入有错先修原文本或明确取消；保存失败保留草稿和错误。不得把失焦后回退当成功；若仍回退，请反馈点类型、原文、失焦动作、保留/保存后值。无需注入input/change事件来绕过真人步骤。

### 2.5 保存草稿、保存为版本与首次加载

1. 完成2.3和2.4的确认后，点顶部 **保存草稿**。预期显示“草稿已保存”，历史版本数量不增加。重复点击仍只保存同一份草稿；“草稿尚未保存为版本”表示还没有对应的不可变快照。
2. 查看 **配置草稿与版本** 下方的问题列表。如果仍有地址、名称、初值或策略待确认，按问题中的实例、DB和点位回对应页面修正并确认。草稿可以分次保存，准备运行的配置应先补齐确认。
3. 点 **保存为版本**。在“保存为版本与清理确认”弹窗核对将生成的编号和待清理历史 → **确认保存为版本**。预期新版本进入列表；**取消**则不创建版本、不删除历史。若内容与最新版本相同，弹窗提示“不重复生成”，确认后数量不变。
4. 如目标正在运行，到 **工作台 → PLC_Test → 停止**，等状态停止、连接释放。首次尚未加载的实例可直接进入下一步。
5. 到 **配置中心 → 实例 → 配置版本与加载**，在“实例”下拉框选 **PLC_Test**。在刚保存的版本行点 **预览加载**。左侧勾选框是给批量删除用的，不是应用版本的入口。
6. 在“停机加载预览”核对全部点的名称、操作和原因。首次加载三点应初始化；已有运行内存时，保留或初始化以清单为准。“删除”行表示旧内存中不再存在的点，不是删除历史版本。需要全部恢复初值时可勾 **明确初始化所有点**，重新核对清单。
7. 勾 **已核对保留、初始化与删除清单；加载后仍保持停止。** → **确认加载并保持停止**。预期该实例的“已选中”和“实际已加载”都指向目标版本，状态仍停止；首次三点值为 `false/7/20.5`。
8. 顶部摘要可显示“已加载 vN · 与最新一致”；若最新版本不同则显示“待加载”。问号可查完整身份。保存草稿、保存版本和加载都不会自动启动；下一步按2.6启动。

如预览未打开或出现校验提示，按[版本切换与错误说明](#switch-version)处理；不要把“保存成功”理解为已经加载。

### 2.6 启动、运行值与恢复

1. **工作台** → PLC_Test **启动**。预期运行中，监听端点明确；有错误查日志而不重复创建实例。
2. **在线值** → PLC_Test，核简短的已加载版本、DB31、类型和地址；版本旁问号可看完整身份。观察数秒：BOOL约每1500ms翻转；INT保持7；REAL按0–100/10000ms斜坡运行，启动后不承诺停留20.5。“更新时间”应为上海日期时间到秒，悬停表头问号查看定义。初始化/加载、成功提交及重置会记录日历时间；只刷新、拒绝的写入或规则值未变时不会推进。可见页面最多约1Hz刷新，同秒内多个提交可显示相同时间，应结合点提交序号核对；单帧不能证明翻转。
3. INT点 **普通写入**，输入 `12`，核旧值、loaded revision、epoch和point seq；勾确认 → **确认本次写入**。预期值12/序号推进，配置初值仍7，规则点普通写不可用。未知回执先刷新，不能自动重试。
   操作列表头的问号解释普通/维护写入。普通写入记为界面来源，不会发出S7客户端请求；当前INT已配置为界面写入。一次性维护只适用于允许维护的hold点（owner为客户端或无写入方），只改这次当前值，不改初值或归属，也不定时自动还原，后续客户端可覆盖。本例不要求改权限来试维护写入；规则点与停止状态的禁写规则保持。
4. **暂停规则**冻结规则时间，不让出规则owner；**恢复规则**继续；**停止**释放监听/连接并保留同进程值12。停止后 **重置运行值**，读清丢弃提示再确认，预期停止态恢复 `false/7/20.5`，不会启动。
5. 需要试持续固定值时，再按[4.4可选示例](#fixed-example)操作；首次跑通三个点不需要额外改模式。
6. 正常关闭窗口，有dirty时按意图保留/保存草稿并关闭/放弃/取消；同一profile重开应按持久selected版本初始化且停止、连接0，不恢复上次运行意图或手改值。保存草稿并关闭也不发布或加载新版本。不要强杀/删除库验证。

<a id="version-management"></a>

### 2.7 版本保留和删除

1. **配置中心 → 实例 → 配置版本与加载**显示整个工作区历史。**使用状态**列出全部实例的使用原因：最新版本、已选、实际已加载、有效加载预览占用属于使用保护，勾选框和**删除**均不可用；停止PLC也不解除已加载配置。不存在强制解除这些保护的按钮。
2. **回退保留（删除须确认放弃）**属于可以主动放弃的保留。一个版本仅有回退保留时，可以点**删除**。弹窗按版本号、保存时间列清单，并在“需放弃回退保留的实例”列显示全部受影响实例。阅读提示，勾**我确认放弃清单内全部实例的回退保留，并删除这些版本**，才能点**确认删除清单内版本**。此操作同时解除这些回退保留和删除版本，不改变当前已选、已加载版本、运行值或启停状态。若还被任何实例使用，则仍不能删除。
3. 普通未引用历史点**删除**后也使用同一清单确认，无需勾回退放弃。提交前**取消**不改版本数量或回退记录；确认成功只删除清单内版本，当前已选/已加载版本保持。提交时服务端重新检查全部引用；任何一项变化就整批不执行，需取消、刷新并重新预览。回执未知时先重读核对，不重复提交；此时关闭提示不能撤销已提交操作。
4. 批量清理：在表格最左勾选需要处理的版本；表头全选仅选择**当前页**可处理项，自动排除使用保护项。核“已选N个版本” → **批量删除**，核对清单数量、每个版本和全部回退实例，再按上一步确认。提交前取消应保留全部版本及回退保留，并清空勾选；确认成功只移除清单内版本。翻页、**刷新列表**或成功删除后也清空勾选，不跨页累计；单个和批量删除采用相同规则。仅有回退保留的项可勾选，但仍需在弹窗明确放弃。
5. 每个实例只记录一份上一版本的回退保留，真正换版时更新为原先所选版本，不会永久保留所有用过的历史。当前已选且实际已加载同一份配置时，重复确认加载不会再次安装或重置值，也不改写回退保留；要恢复初值使用工作台的 **重置运行值**。无需为了删除某版本而故意再次加载。
6. 取消加载预览、切换目标实例或离开页面会释放本页面预览；完成加载后刷新版本事实。进入实例页或点**刷新列表**会重新读取使用状态，过期预览占用也会移除；刷新不覆盖正在编辑的草稿。若仍不能删除，先核具体实例/使用原因，不删除锁或手工修改SQL。
7. 明确发布新版本时，默认保留最近5份，加上使用保护和回退保留中的旧版，所以总数可以大于5。自动清理不会替你放弃回退保留；具体对象在发布弹窗列出，提交前取消也取消清理，内容不变的发布不新建、不清理。“最近5份”不是禁止手工删除的锁定区，手工删除按上面的使用保护及回退确认判断，最新版本始终保留。
8. 升级启动、重开和保存草稿不会自动裁剪已有历史。版本编号只递增，不因删除复用；例如删除v11后，后续保存不会重新使用v11。来源原件与当前运行值不随版本清理删除。不要为检查上限刻意改联调点位或制造版本。

### 2.8 本轮草稿和版本调整的手工确认

此处是可选检查清单，不是日常操作必做流程；已经完成的项目无需反复执行。沿用原联调profile、实例和点位；以下是操作说明，不代表已由Agent执行。可先验证“取消”路径，实际删除由你核对清单后明确决定。

1. 正常关闭并用原profile的`pnpm tauri dev`重新启动，核原联调实例、最新版本号和总数仍在；实例保持停止。已有未保存提示先确认编辑意图，不直接放弃。进入实例页，核**保存草稿／保存为版本／配置版本与加载／刷新列表／批量删除**。
2. 不改点位，连续两次**保存草稿**，核版本数量不增加。点**保存为版本**，核清单后先取消，数量不变；内容与最新相同时应提示不重复生成。若草稿内容不同，先记录将生成的版本与清理项，不为本轮检查直接提交或制造改动。
3. 找一行仅有回退保留的历史（例如v12，具体以实际状态为准），点**删除**。未勾放弃前确认不可用；核清单中的实例，勾选后再点**取消**，核版本和回退保留仍在。如果该行还有使用保护，应保持不可操作，先反馈原因。
4. 找到两个可处理历史时勾选，核数量，**批量删除 → 取消**，核版本和回退保留均未变。没有两个可处理版本时无需另造历史。实际删除若由你确认，核只移除清单内版本，当前已选/已加载与点位配置保持，旧编号不复用。
5. 已停止的目标可选一个配置完整、能通过校验的版本做 **预览加载 → 取消**，核占用消失、使用状态恢复。旧版若直接出现“完整配置未通过校验或尚有待确认项”，只是预览被拦截，不能计为“打开后取消”通过；不必为了这项检查修旧版或另造版本。需要检查重复加载时，仅用当前已选且实际已加载的同一配置；确认后回退保留、运行值和停止状态应保持，不需要反复换版。
6. 按每一步反馈实际界面、状态与错误，由DS会话继续带下一步。确认本轮增量后再回DAA继续另批S7读取至SQLite联调；阶段B不因此自动完成，阶段C暂不开展。

<a id="switch-version"></a>

### 2.9 切换版本、回退与校验提示

**已有可用版本时，切换不需要重新创建实例、改点位或保存一个新版本。** 切换使用列表中已保存的快照，草稿与运行内存仍分别管理。

1. 完成或取消正在打开的编辑弹窗；有要保留的修改先 **保存草稿**。仅为切换已有版本，不必再点“保存为版本”。
2. 到 **工作台** 找到目标实例 → **停止**，等待状态停止、连接释放；“暂停规则”仍保留服务，不能代替停止。
3. 到 **配置中心 → 实例 → 配置版本与加载**。下拉框选目标实例，例如 `PLC_Test`；按版本号和保存时间找到要使用的行 → **预览加载**。上方实例表的“选择”只切换当前查看对象，不会加载版本。
4. 核对“停机加载预览”的逐点清单，再按下表理解运行值的处理。要放弃本次操作点 **取消**，原已选/已加载版本及回退保留均不变。

| 操作 | 预览与确认后的行为 |
| --- | --- |
| 首次加载 | 按目标版本的DS初值建立运行值 |
| 加载比当前已选更新的版本 | 默认按兼容清单保值；变更点/DB初始化。可勾“明确初始化所有点”，以重算后的清单为准 |
| 回退到比当前已选更旧的版本 | 强制勾选且不可取消“明确初始化所有点”；所有值按旧版DS初值重建，规则时间归零 |
| 当前已选且实际已加载同一份配置 | 重复确认不会再次安装，不重置运行值、代次或回退保留；需要重置时用工作台的“重置运行值” |

5. 确定后勾 **已核对保留、初始化与删除清单；加载后仍保持停止。** → **确认加载并保持停止**。
6. 核对版本使用状态：目标行出现该实例的“已选中 / 实际已加载”；真正换版时，原已选版本成为该实例的“回退保留”。最新版本即使只作回退保留，仍受“最新版本”保护，不能删除。版本旁问号可查完整身份。
7. 回退后若显示“已加载 vN，最新 vN+1，待加载”，表示你有意使用旧版、另有较新快照，并非回退失败。工作台状态应仍停止；到在线值核对实际已加载配置，准备继续模拟时再回工作台 **启动**。客户端需重新连接对应端点。

版本只保存配置和初值，不保存历史运行现场。回到旧版本不会找回当时的手改值；停止期间的内存保值、换版保值与退出后重新初始化是不同动作。切回更新版本仍按本次预览清单处理，不会自动恢复上一次切换前的现场值。

| 提示或现象 | 含义与处理 |
| --- | --- |
| 完整配置未通过校验或尚有待确认项 | 检查的是本次选中的历史快照；可能有地址、命名、初值、策略未确认或配置冲突，不能仅凭这句判断具体点。当前界面不会展开历史加载失败的逐项原因。预览在校验阶段被拒绝，未切换版本；保留现有可用版本。需要修复时，在当前草稿补齐问题和确认后另存新版本，确认当前草稿不会改写旧快照 |
| 保存草稿后在线值没变 | 草稿尚未发布/加载，或该实例仍在用旧版本；按2.5完成保存为版本、停机加载，再启动 |
| 删除不可用 | 看“使用状态”中的全部原因；最新、任意实例已选/已加载或有效预览都受保护。仅有回退保留时才可按2.7明确放弃并删除 |
| 预览过期、版本或引用变化 | 取消当前弹窗 → 刷新列表 → 重开正确版本的预览，重新核对 |
| 回执未知 | 操作可能已提交；先刷新版本事实并核实际已加载/运行状态，不重复点击确认。取消提示不能撤销已提交操作 |

5. 恢复：看错预览就取消；保留只进本地草稿。保存失败原待修草稿仍在，不能认为已经持久化或加载。

### 4.3 兼容性失败、模式联动与取消

1. 只筛DB31，选BOOL与INT → **批量编辑策略**，“模式”选统一设置 **布尔翻转**。预期列出INT点的DB/点ID/类型及不支持原因，整个候选不能保留，没有跳过INT或先改BOOL。取消后两点原策略都不变。
2. 同样混合选择，仅“初值”统一设置 `7`，BOOL不兼容，预期同样整批失败；取消不改草稿。不要用这种方式统一不同类型初值。
3. 只选INT与REAL，可统一数值fixed12：模式统一设置 **持续固定**，联动区给出owner=rule、三写禁止、完整fixed规则；固定值填12。预览每点全部前后属性/来源；原初值保持各自7/20.5。勾核对后保留才一次性改这两点。此操作不写运行值。
4. 要保留原模式/owner仅改读取权限，模式/owner/规则应留“不修改”。独立改规则须选择完整规则种类及全部参数；不能将其它mode旧参数混合。恢复模式继承不自动清owner/rule，若仍冲突，应把需要恢复的相关字段也明确选“恢复继承”，预览无误才提交。
5. 验收可在第3步先 **取消**证明无改动；若真的保留并保存，用单点恢复2.4中的策略、重新确认，再按停机加载流程恢复教程状态。父DB/其它PLC/未选点不得改变。

### 4.4 持续固定值示例（可选）

1. 在自己的教程配置中，对 Setpoint_Int 点 **编辑策略** → **持续固定**。核owner变为持续规则、三项写权限禁止；固定值填 `12`，DS初值仍留 `7` → **完成编辑**。
2. 只选该点 → **保存草稿并确认所选初值/策略**。固定规则12和初始化7是两个字段；只保存不会改变当前运行值。
3. 需要实际运行时按2.5 **保存为版本 → 停止 → 新版行预览加载 → 确认加载**，再工作台 **启动**，应由规则持续产生12。已有点是否保值按预览清单判断，不保证加载时先出现7。
4. 继续原普通写示例时，把此点改回 **保持 → 界面 → 普通写允许**，客户端写/维护写禁止、初值7；完成编辑、只选该点保存并确认。需要应用恢复后的配置时，再保存为版本并停机加载、启动。

## 5. 其它运行边界和错误恢复

- 层级逐属性覆盖为实例→DB→不重叠region→point；region以bit范围表示，须整字段覆盖，不能重叠或切开INT/REAL。下方区间入口可新增、编辑范围、编辑策略、移除；改父策略/范围后核受影响点来源和确认。默认值是类型/系统默认，不是假造确认。
- S7 client owner的hold点可按显式权限允许一次维护写；在线值弹窗核旧值/version/epoch/seq，维护不会改配置初值或owner。持续规则即使暂停也不让写权。未知回执先读回和重开，不自动重试，后续并发写会使读回无法证明原请求。
- 同源重导须在文件行选原lineage、声明行选已有目标DB，明确闭包和号，预览再确认。结构/地址/类型变动使相关确认失效；旧初值只是候选，不自动转换。重新核布局/命名/初值/策略。
- 保存后在线值未变：先核草稿是否已保存为版本，再比较loaded与latest，停止后在正确版本行预览加载。保存草稿或发布版本均不更新运行值。
- 最多8实例/32DB每实例/4096叶点每实例/64KiB每DB为配置上限，不是容量承诺。新实例示例可用30103，需自己确认端口可用；各实例UUID独立，名字不是身份。此手册不要求16连接或性能矩阵。
- 日志与存储中点刷新、填实际事件名筛选、清空恢复；每页50条、有界保留。“时间”列表头问号说明上海时区与秒级显示；版本原UTC时间只转换一次。新原生日志记录带有`+08:00`的`timestamp`，原始毫秒保留，须在开发进程重新编译/启动后生效；在线值新增的`updatedAt`同样需要新Rust进程，缺字段时明确显示未记录，不把计数格式化成日期。旧日志没有日历字段时显示“未记录日历时间”，不按文件修改时间或单调ns倒推。单调计数单独保留，用于排序和耗时。既有SQLite UTC字段/版本历史和原始日志保留，不在本步骤迁移或重写。观测降级/日志丢失不等于操作成功。数据库损坏/不兼容/只读/不足时保留原库和错误，不改schema、不删历史、不覆盖空库。
- 当前有限S7配置为端口30102/rack0/slot1、Calling TSAP256（0x0100）、Called TSAP257（0x0101）；使用支持自定义端口客户端，完整字段和逐点权限约束仍生效，BOOL用位寻址。本文不启动外部客户端或联调。
