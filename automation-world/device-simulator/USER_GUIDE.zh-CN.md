# DS 设备模拟器使用手册

[English](USER_GUIDE.md) · [工程入口](README.zh-CN.md) · [构建说明](BUILD.zh-CN.md) · [截图来源](docs/user-guide/images/README.zh-CN.md)

本手册先用三个手工点跑通一个实例，再导入两个 DB 和一个 UDT。示例使用本机回环地址和合成数据；DB 号、点名和端口是可编辑示例。DS 独立运行，无需启动 DAA、SMA 或 Backend。

> **当前已知限制（2026-10-22）**：自定义非零初值输入在真实键入后会回退旧值；持续固定值框有相同事件绑定风险，待另批修复。原拟初值7/20和导入count10未跑通，不作为成功预期。本手册主流程显式使用BOOL `false`、INT/REAL `0`，再用在线普通写入 `12` 演示非零运行值。产品最终验收仍有此未关闭问题，详见[复现与证据边界](#非零初值输入的复现与证据边界)。

## 1. 启动与准备

### 1.1 从源码启动桌面程序

已验证环境为 macOS 15.7.7/arm64，Node 22.19.0、pnpm 11.11.0、Rust/Cargo 1.89.0、CMake 4.0.2、Apple clang 17/SDK 26.1。先按[构建说明](BUILD.zh-CN.md)准备工具链；首轮编译可能需要获取锁定依赖。本仓库未提供经本轮验证的安装器或其它平台安装步骤。

在仓库根目录打开终端，执行：

```sh
cd automation-world/device-simulator
pnpm install --frozen-lockfile
export DS_PROFILE_DIR="$HOME/aiis-ds-demo"
pnpm tauri dev
```

`DS_PROFILE_DIR` 是本教程可选的隔离目录；请选一个归自己所有的新绝对路径。DS 会创建配置和日志，不要指向 DAA 或未知既有数据目录。之后重开教程必须继续使用同一路径。未设置时，程序使用 Tauri 的 DS 应用本地数据目录；可在“日志与存储”查看实际配置库路径。macOS WebKit 数据另按持久 store UUID 保存，不能只删除配置库来“清理一切”。

预期：出现原生 DS 窗口。首次打开这个 profile 时没有实例，也没有 S7 监听。原生适配库由工程自动构建、链接，不要求旧 `DS_G0_*` 变量或临时预编译库。`pnpm dev` 只启动 `127.0.0.1:15194` 的浏览器前端；没有桌面 bridge 时会提示桌面操作不可用，不能用于完成本教程的保存、加载或启停。

### 1.2 pnpm store 提示怎样处理

如遇 `ERR_PNPM_UNEXPECTED_STORE` 或提示重建 modules，先查看 `pnpm store path`，并核对当前工程 `node_modules/.modules.yaml` 的 `storeDir`。它是生成的安装元数据，不能据此修改项目锁文件。历史验证曾使用角色自有临时 store；不要把 `/private/tmp/arch-aw-005-r5-exec/...` 写成产品长期依赖。

2026-10-22 只读核对时，此工作树的 store 为 `/Users/jason/Library/pnpm/store/v11`；你的机器可能不同。需要改用当前用户 store 时，在 DS 目录用同版本 pnpm 重新执行 `pnpm install --frozen-lockfile`，核对提示仅重建本工程 `node_modules` 后再继续。不要用删除 profile、改锁或升级依赖来解决 store 不匹配；不能确认提示范围时，保留完整输出排查。

### 1.3 页面与四个关键动作

| 页面 | 本教程用途 |
| --- | --- |
| 工作台 | 看运行状态、版本事实，启动、暂停规则、恢复规则、停止、重置运行值 |
| 配置中心 → 实例 | 新建实例；选择保存版本，预览并停机加载 |
| 配置中心 → DB 点位 | 新建 DB/手工点、导入、地址与命名确认 |
| 配置中心 → 模拟与读写策略 | 逐点设置初值、写入来源和规则 |
| 在线值 | 看实际已加载 DB/地址/值，普通或维护写入，连接面板 |
| 日志与存储 | 查有界日志、配置库路径、存储与日志丢失计数 |

1. **保留编辑**：把弹窗编辑放回本地草稿，还没保存。
2. **保存候选**：保存配置和不可变版本；不加载、不启动。未完成的候选可以保存，问题会列在配置条中。
3. **确认加载并保持停止**：把明确选择的保存版本加载进内存，仍不监听。
4. **启动**：显式打开该实例的监听，并推进规则。

## 2. 案例一：手工 DB31

### 2.1 创建 PLC_Test 实例并保存

1. 点击左侧 **配置中心 → 实例**，再点击 **创建实例**。工作台的“创建实例”只会导航到此页，仍需点击此页按钮打开编辑器。
2. 在“编辑实例”填写下表，点击 **保留编辑**。
3. 点击上方 **保存候选**；等待“有未保存修改”变成“已保存”。此时“尚未配置 DB”等问题是下一步待完成项，不代表保存失败。

| 字段 | 示例输入 |
| --- | --- |
| 名称 | `PLC_Test` |
| IPv4 回环地址 | `127.0.0.1` |
| 端口 | `30102` |
| 机架号 / 槽位号 | `0` / `1` |
| 客户端 TSAP（十进制） | `256` |
| 最大已建立连接 / 最大握手连接 | `16` / `4` |

预期：实例表有 `PLC_Test`、端点 `127.0.0.1:30102` 和 `16/4`。尚未加载时，工作台可能还没有它的运行行；不要因此重复创建实例。

![实例编辑字段](docs/user-guide/images/02-instance-editor.png)

### 2.2 建立 DB31 和三个点

1. 进入 **配置中心 → DB 点位**，在实例下拉选择 `PLC_Test`，点击 **新增 DB**。
2. 将 DB 名称设为 `Manual_Demo`，**DB 号**设为 `31`，**DB 长度（字节）**设为 `8`，保持“启用”。不要沿用自动分配的 DB 号或默认长度 1。
3. 点击 **新增手工点**，每次按下表填写后点击 **保留编辑**。三个点都保持“启用”；显示名称可填写表内中文说明，点“名称”使用表内 ASCII 名。

| 名称 | 显示名称 | 数据类型 | 字节偏移 | 位偏移 | 人工地址确认理由示例 |
| --- | --- | --- | --- | --- | --- |
| `Run_Bool` | 运行标志 | BOOL | `0` | `0` | `合成教学：DB31.DBX0.0，只映射此位。` |
| `Setpoint_Int` | 设定值 | INT | `2` | 不显示 | `合成教学：DB31.DBW2，占字节2和3。` |
| `Temperature_Real` | 温度 | REAL | `4` | 不显示 | `合成教学：DB31.DBD4，占字节4至7。` |

每个点都必须填写理由；非 BOOL 选择类型后不保留 bit。确认三行地址分别显示 `0.0`、`2`、`4`，然后点击 **保存候选**。最高触达字节为 7，长度 8 恰好容纳这些点；未映射的空隙不自动成为可读写点。

![手工点编辑与人工地址理由](docs/user-guide/images/03-manual-point.png)

### 2.3 确认完整人工地址，再确认名称

1. 确认顶部已保存，点击 **确认完整人工地址**。手工 DB 的“预览标准地址”不可用，不要把它转成导入 DB。
2. 在理由输入框填写：`合成教学DB31：BOOL位0.0，INT字节2至3，REAL字节4至7，长度8，地址无重叠。`
3. 点击 **预览**。弹层会显示“完整地址方案已校验”；当前布局弹层没有逐地址行表，不要把空行区当失败。点击 **确认**，保存这份完整 DB 地址证明。
4. 回到点表核对 DB31 长度和三行地址。勾选点表表头复选框，选中本页三个点；点击 **预览所选点命名**。
5. 在预览表核对 `Run_Bool`、`Setpoint_Int`、`Temperature_Real`，点击 **确认**。手工合法名称保持原样，不会自动改成 DB 前缀名。

选择规则：表头只选择**当前页**；10/20/50 分页下跨页选择可累计，切 DB 或实例会清空选择。命名和批量初值/策略确认只提交明确选中的点。点表“待确认”列指初值/策略，地址和名称已确认后仍可能显示待确认。

![完整人工地址确认](docs/user-guide/images/04-manual-layout.png)

### 2.4 逐点设置初值与规则，并明确确认

进入 **配置中心 → 模拟与读写策略**。选择 `PLC_Test`，层级选 **点**，DB 选 `Manual_Demo`，依次选下面三个点。不要误改实例/DB 层级。

每个点都按表填写；DS 初值处勾选 **显式覆盖**，本例保留勾选后产生的默认 `false` 或 `0`，不要尝试键入非零初值。完成该点后点击本页 **保存并确认所选初值/策略**，等待已保存，再换下一个点。这个按钮会同时保存并确认当前点，不必先另点“保存候选”。

| 字段 | Run_Bool | Setpoint_Int | Temperature_Real |
| --- | --- | --- | --- |
| 模拟模式 | 布尔翻转 | 保持 | 斜坡 |
| 唯一写入来源 | 持续规则 | 界面 | 持续规则 |
| 客户端读取 | 继承（默认允许） | 继承（默认允许） | 继承（默认允许） |
| 客户端写入 | 禁止 | 禁止 | 禁止 |
| 界面普通写入 | 禁止 | 允许 | 禁止 |
| 一次性维护写入 | 禁止 | 禁止 | 禁止 |
| DS 显式初值 | `false` | `0` | `0` |
| 最小值 / 最大值 | `0` / `1` | 不显示 | `0` / `100` |
| 周期（毫秒） | `1000` | 不显示 | `10000` |
| 相位（周期） | `0` | 不显示 | `0` |
| 翻转半周期（毫秒） | `1500` | 不显示 | 不显示 |

翻转使用半周期1500ms，完整翻转周期约3秒；截图中通用周期字段保留1000ms，不用它推算翻转。维护写若显示继承，其默认仍是禁止；本表明确禁止的权限以最终有效策略为准。

切换自动模式时，UI 会选择持续规则 owner 并禁止外部写，仍须核对最终表单。保持模式的 `ui` owner 必须配普通界面写“允许”、客户端写“禁止”；把两种写都允许会被权限编译拒绝。“保持”不是“持续固定”：前者保留合法写入值，后者由规则持续产生固定值。

回到 **DB 点位**，重新选择 DB31，预期三点均为 **已确认**。若后续改了 DB 号、长度、结构、类型或地址，应重新检查地址/命名并重新确认受影响初值与策略。旧值仍可作编辑候选，不代表新布局已获确认。

![逐点初值与读写策略](docs/user-guide/images/05-policy.png)

### 2.5 选择最新版本，停机加载

1. 进入 **配置中心 → 实例**，在“选择保存版本并停机加载”卡片选择 `PLC_Test`。
2. 在 **不可变保存版本** 下拉明确选择本次操作产生的**最高保存序号**（标签为“序号 · 时间”）。下拉不会在每次保存后自动改选最新版本；不要凭原有选中项加载旧候选。
3. 确认无未保存修改、实例未运行，点击 **预览加载与保值**。若校验阻断，先按配置条定位待确认点，不要反复点击启动。
4. 首次加载预览应将三点列为初始化。核对实例、三点与保留/初始化/删除清单；本次保持“明确初始化所有点”未勾选即可，首次加载本来就需初始化。
5. 勾选 **已核对保留、初始化与删除清单；加载后仍保持停止**，点击 **确认加载并保持停止**。

预期：工作台出现 PLC_Test，状态 **已停止**、连接 0；selected 与 loaded 版本对应本次选定版本。停止态在线值为 `false`、`0`、`0`。saved 是候选历史；selected 是持久选择；loaded 是当前内存版本，三者可能不同。

![停机加载预览与明确确认](docs/user-guide/images/06-apply-preview.png)

### 2.6 启动并观察在线值

1. 在 **工作台** 对 PLC_Test 点击 **启动**。预期状态 **运行中**，端点开始监听；失败时看错误和“日志与存储”，不要换端口掩盖冲突。
2. 进入 **在线值**，选择 PLC_Test；核对页头 loaded revision、表内 DB31、地址/类型/值，而不是只看点名。
3. `Run_Bool` 每 1500 ms 翻转；`Setpoint_Int` 保持 0；`Temperature_Real` 启动后按模拟时间在 0–100 间、周期 10000 ms 运行。**0 是本例加载/重置后的停止态初值；启动后温度按斜坡运行，不承诺继续保持0。**
4. UI 可见时最多约 1 Hz 刷新；观察数秒及点提交序号/写入来源。单帧不能证明 BOOL 是否翻转，500 ms 半周期还可能与刷新混叠。浏览器后台/隐藏页不持续刷新。

![实际加载版本与在线值](docs/user-guide/images/07-online-values.png)

### 2.7 普通手改、暂停、停止与重置

1. 在线值找到 `Setpoint_Int`，点击 **普通写入**，将输入改为 `12`。核对页头已加载版本，以及弹层旧值、代次和点提交序号，勾选 **已核对本次值、版本与提交序号**，点击 **确认本次写入**。
2. 预期值为 12，来源为界面普通写入，点序号推进；配置初值仍为 0。两个自动规则点的普通写按钮应不可用。
3. 工作台点击 **暂停规则**：状态变“规则已暂停”，BOOL/温度规则冻结；监听、读取及符合策略的 hold 写入仍可用，暂停不会把规则点让给 UI。
4. 点击 **恢复规则**：从冻结模拟时间继续，不补跑暂停期间的时间。
5. 点击 **停止**：等待已停止和连接释放，停止监听并冻结规则；同进程内保留运行值12。再次启动仍从这份内存继续，不等于 reset。
6. 停止后点击 **重置运行值**，核对“丢弃全部当前值”的提示并 **确认**。预期仍停止，恢复当前 loaded 版本初值 `false/0/0`，规则时间归零；不会自动启动。

### 2.8 正常退出并重开

保证需要保留的配置已经保存且已显式加载。关闭原生窗口；若有未保存编辑，按意图选择 **取消**、**保存并关闭** 或 **放弃编辑并关闭**。“保存并关闭”只保存候选，不替你加载它。

用第1节同一个 `DS_PROFILE_DIR` 再执行 `pnpm tauri dev`。预期恢复 selected 配置、loaded 版本重新初始化、状态 **已停止**、连接 0；不会恢复运行意图或上次手改的12。若需要看到运行值，选对实例并等快照刷新。退出终端 watcher 与正常窗口关闭是不同动作；不要用强制杀进程验证保存成功。

## 3. 案例二：导入 Alpha/Beta 多 DB 与 Measure UDT

此例在同一个 PLC_Test 中保留 DB31，新增 DB71/88。先在工作台 **停止** PLC_Test，等待连接释放；所有本地编辑先 **保存候选**。不要修改两个样例文件。

### 3.1 选择文件、声明和闭包

1. 进入 **DB 点位**，选择 PLC_Test。在“多源 DB / UDT 导入”卡片的文件选择器同时选择仓库中的：
   - `automation-world/data-acquisition-agent/src-tauri/tests/fixtures/source-import-multi-db/multi.db`
   - `automation-world/data-acquisition-agent/src-tauri/tests/fixtures/source-import-multi-db/types.udt`
2. 首次导入保持每个文件为 **作为新来源**，点击 **扫描声明**。文件行、声明和 UDT 选项含文件名/批内序号/短身份；同名文件也要据此区分来源。
3. 只勾选下表两行。扫描会显示更多 DB，它们全部不选；选择器的默认 DB 号1不是本例目标。

| DB 声明 | 目标 DB | DB 号 | 显式 UDT 闭包 |
| --- | --- | --- | --- |
| Alpha（multi.db） | 新增 DB | `71` | 留空，不选任何 UDT |
| Beta（multi.db） | 新增 DB | `88` | 仅选 `Measure`（types.udt） |

不要选 Frame/Spare；不要为 Alpha 选 Measure，也不要因文件含六个 DB 就全部导入。点击 **预览导入差异**，核对 Alpha/Beta 完整树、目标号、保留的 DB31及提示“:= 和 BEGIN 初值均不导入”，再点击 **确认保存导入候选**。这会保存导入候选，仍不改运行 image 或启动监听。

**操作状态：本步尚未由本次取图完成，待Owner手动反馈；当前无配图。**

### 3.2 每个导入 DB 确认标准完整布局

在 DB 点位下拉选择 **Alpha · DB71**，点击 **预览标准地址** → 核对预览成功 → **确认**。随后选择 **Beta · DB88**，重复同样操作。两个 DB 都不能省略。

本例不含 STRING；共享 `siemens-step7-v20-standard-word-v1` 按完整非优化树进行标准 word 对齐，预期如下。以确认后的实际点表为核对面；此布局不是实机 TIA 地址证明。

| DB / 长度 | 结构路径 | 类型 | 字节.位 |
| --- | --- | --- | --- |
| DB71 / 4字节 | ready | BOOL | `0.0` |
| DB71 / 4字节 | count | INT | `2` |
| DB88 / 8字节 | unit.running | BOOL | `0.0` |
| DB88 / 8字节 | unit.value | REAL | `2` |
| DB88 / 8字节 | bytes[3] | BYTE | `6` |
| DB88 / 8字节 | bytes[4] | BYTE | `7` |

REAL 在此 profile 是 word 对齐，不能自行改为字节4。数组下界为3，结构身份中保留 `[3]`/`[4]`，不是重排成 `[0]`/`[1]`。

### 3.3 每 DB 选点、预览命名并确认

1. 选择 Alpha/DB71，表头选中本页两点 → **预览所选点命名** → 核对 → **确认**。
2. 切 Beta/DB88 后选择已清空；重新表头选中四点 → **预览所选点命名** → 核对 → **确认**。

| 原始路径 | 本例预期名称 |
| --- | --- |
| Alpha.ready | `DB71_ready_Bool` |
| Alpha.count | `DB71_count_Int` |
| Beta.unit.running | `DB88_unit_running_Bool` |
| Beta.unit.value | `DB88_unit_value_Real` |
| Beta.bytes[3] | `DB88_B6_Byte` |
| Beta.bytes[4] | `DB88_B7_Byte` |

Index 段采用地址兜底，数组名不是随意拼接的 `bytes_3`。先有地址证明，命名才能使用地址兜底；命名按整个实例保留名称检查冲突，不是每 DB 各自允许重名。

### 3.4 设置 DS 初值、确认，再重新加载运行

1. 进入 **模拟与读写策略**，实例选 `PLC_Test`，层级选 **DB**，DB选Alpha（DB71）。设置 **保持**、**无写入 owner**、客户端读 **允许**，客户端写/界面普通写/维护写均 **禁止**。DS初值保持继承，不勾DB统一显式初值；混合BOOL/INT按各点类型默认false/0。点击 **保存候选**。
2. 回到 **DB 点位**，选Alpha。确认两点没有显式点层覆盖；若有，在点层将对应属性改回继承并保存。表头勾选本页全部两点，点击 **保存并确认所选初值/策略**。这是确认当前有效值，不是批量赋规则。
3. 对Beta（DB88）重复上述DB层设置、保存；回点位选其全部四点，一次确认。两BOOL=false，INT/REAL/BYTE=0。`multi.db` 的 `count : INT := 7` 不导入初值；count的0来自DS类型默认值，不是导入7，也不声称原拟10已输入。此流程共两套DB策略，不需逐点编辑六次；新导入点应无显式point overrides。
4. 核对DB71两点、DB88四点均已确认，原DB31未被删除/改绑。实例页明确选**最高保存序号**，点击 **预览加载与保值**，核对新增DB初始化及原点清单，勾选确认后 **确认加载并保持停止**。
5. 工作台 **启动**，在线值核对实际loaded revision、三个DB和九点。首次加载count应为0；DB31原hold值是否保留以加载清单为准。本次取图尚未提交导入，此处是按现有实现提供的操作步骤，待Owner反馈，不是已完成的导入运行证明。

## 4. 进阶操作

### 4.1 一次性维护写入

仅在需要人工覆盖 client-owner 或无owner的 **保持** 点时使用。例如将 `DB71_count_Int` 的 owner改为 **S7 客户端**，客户端写 **允许**、普通界面写 **禁止**、一次性维护写 **允许**，其余值按原意保留；**保存并确认所选初值/策略**，停止→选最新版本→预览/确认加载→启动。

在线值中点击该点 **一次性维护写入**，填写新值、核对旧值/版本/代次/点序号，勾选确认后提交。它不改初值，不转移owner；客户端之后仍可覆盖。自动规则点即使暂停也不能维护写。默认维护权限关闭，不能用它绕过普通写保护。

若显示回执未知，不自动重试；先刷新当前值/序号并重新核对。若已有后续并发写，当前读回值不能证明原操作成功。版本或序号过期时，关掉旧弹窗，刷新后重新确认。

### 4.2 STRING 与人工完整地址

STRING 类型可用 `STRING[1..254]`；占用最大长度+2字节（S7 max/actual头和完整字符区域），只允许ASCII。含 STRING 的导入 DB 不能用“预览标准地址”，必须为**整 DB 的每个点**填写不重叠地址/理由、设足DB长度，保存后用“确认完整人工地址”给整DB理由，再命名与确认初值/策略。此例不演示STRING导入，不能从其它字段推测其地址。

### 4.3 重导与失效

同一来源更新时，文件行明确选择原 **来源版本系列**；DB行选择已有目标DB，而不是“新增DB”，并再次明确选闭包/DB号。先查看差异再确认。相同原字节、绑定和闭包可返回unchanged；未选DB/实例不应被改写。DB号/长度/结构/地址/类型变更会使受影响确认失效，旧初值只作候选且不自动转换。重新确认布局、命名、受影响初值/策略，选择新版本停机加载；不要为了“消除错误”反复新建来源或勾所有UDT。

### 4.4 保留运行值、全部初始化与回滚

默认加载预览按兼容清单保留运行值：稳定点身份/地址/类型/值语义兼容的hold点可保留；新点或变更DB/值语义按清单初始化。规则定义改变等情况也可能重置规则时间。改显示名或连接上限不等于应该丢hold值；仍须核对清单。保留失败会明确失败，不能当成已加载。

需要清空全部运行值时，预览中勾选 **明确初始化所有点**，重新核对清单并确认。选择比当前selected更早的保存版本回滚时，预览强制全部初始化；历史revision是完整已保存配置，不能靠当前草稿补齐它的确认。相同已加载版本可能返回already_loaded，不代表进行了一次隐式reset。

### 4.5 多实例与连接

可在实例页新增第二实例，例如本机端口30103；每个实例独立选择保存版本并加载。名称不是身份，不用复制UUID。实例内DB号唯一，不同实例可有相同DB号；监听端点不能冲突。最多8实例、32DB/实例、4096叶点/实例、64KiB/DB是配置上限，不是8×16连接容量承诺。C/H与全局资源预算均可能拒绝新连接。

在线值下方 **连接** 面板属于当前所选实例。核对peer、连接身份、握手/已建立/关闭中、预留字节及时间；横向滚动表内查看技术字段。点击 **关闭此连接**，核对所选连接后 **确认**，只关闭此连接。已提交写不会回滚；客户端重连会产生新连接身份。无外部客户端时空表和连接0是正常现象。

### 4.6 S7 客户端参数（说明，不启动客户端）

| 参数 | PLC_Test 示例 |
| --- | --- |
| 地址 / TCP端口 | `127.0.0.1` / `30102`，不要误用默认102 |
| Rack / Slot | `0` / `1` |
| 本地/Calling TSAP | 十进制`256`，十六进制`0x0100` |
| 对端/Called TSAP | 此rack/slot下为`0x0101`（257） |
| DB31点读取 | BOOL位0.0；INT字节2、长2；REAL字节4、长4 |

选择支持自定义端口和TSAP的兼容S7客户端；部分库可从rack/slot生成Called TSAP。只有启动后的实例可连接，暂停规则仍保留通信；同进程stop/start会使客户端断开再重连。运行在其它电脑上的127.0.0.1指向那台电脑，不会到达本机DS。

请求必须覆盖完整已映射字段并满足逐点权限；不要批量读取含未映射padding的整个DB。BOOL整字节请求会触达其它7位，可能被拒，按实际bit读取。STRING须完整n+2字节。当前有限协议为S7 PDU480、最多4items、单item最多256B、AMQ1；多项按item返回，前项已提交时后项失败不整体回滚，断连/超时可能结果未知。配置DB长度上限不等于支持任意大包。

本教程不运行 DAA 应用或 DAA→SQLite联合采集。已有独立S7兼容证据、实际范围和当前验收状态见[任务记录](../../plans/ARCH-AW-005-ds-g0-prototype-validation/tasks.md)与[独立核验记录](../../plans/ARCH-AW-005-ds-g0-prototype-validation/checklist.md)；阶段C、真实设备和完整PLC CPU行为不在这里展开。

### 4.7 多点配置：当前能批量做什么

相同策略可利用逐属性继承：**实例 → DB → 不重叠区间 → 点**，更低层显式值优先。例如一个DB中的点都只读/保持时，在“模拟与读写策略”选择DB层，设置保持、无写入owner、客户端读允许、其它写禁止，初值保持继承/按类型默认，然后点击配置条“保存候选”。混合BOOL/数值/STRING类型不能盲目共用同一个初值或同一自动规则；已有点层覆盖也不会被父层修改清掉，需要时在对应点相关字段选“继承上层”。

地址/名称已确认后，回“DB点位”选这个DB：用表头勾当前页（或逐页累计勾选），点击 **保存并确认所选初值/策略**。这会确认选中点当前的有效初值/策略，**不会批量给点赋同一规则或改参数**。切DB/实例需重新选点；确认后仍需选版本停机加载才能影响运行。

每点需要不同斜坡、周期或读写来源时，目前仍在点层逐个编辑；当前没有多选统一赋值、策略表格、XLSX配置导入/导出入口。旧[Python虚拟PLC工具](../../tools/plc/s7-virtual-plc/README.zh-CN.md)的init-profile按DB sheet/一行一点生成XLSX，含mode/fixed_value/min_value/max_value/hold_seconds/period_seconds/sequence_values；它属于另一个程序，不能直接导入DS，也不能把秒单位直接填进DS毫秒字段。表格编辑、多选赋规则、模板及导入导出可作后续需求讨论，待另批实现；本手册不增加这些功能或用旧工具替代DS运行。

## 5. 常见阻断与排错

| 看到的现象 | 检查和恢复动作 |
| --- | --- |
| 保存候选按钮禁用 | 先在当前编辑弹窗点“保留编辑”或取消，等待busy结束；没有桌面bridge时改用原生启动 |
| 导入/地址/命名按钮禁用 | 先保存dirty草稿；选对实例/DB；命名还要勾点；手工DB不提供标准地址 |
| 地址已确认但仍待确认 | 点表确认列是初值/策略；逐点设置、显式确认，再看配置条问题位置 |
| 标准地址失败 | 检查完整DB、显式UDT闭包和受支持类型；STRING/人工地址按整DB人工方式处理，不猜地址 |
| load被配置问题阻断 | 按实例/DB/点定位未确认项；确认版本下拉选的是最新序号，而非旧候选 |
| 已保存但在线值没变 | 保存不加载；停止后预览/确认加载。在线值显示loaded，不是draft |
| 启动失败/端口占用 | 核127.0.0.1:30102及日志；先由占用进程所有者处理，不杀未知进程、不盲换端口 |
| profile_in_use | 使用同目录的另一DS仍持有锁；正常关闭该自有实例，不删除锁文件抢占 |
| 草稿ETag冲突 | 保留自己的编辑意图，重新读取当前事实后重做；“重新读取草稿”会丢未保存编辑 |
| 写按钮禁用 | 看实际loaded owner/mode/允许项及running/paused状态，刷新stale；规则点不让权 |
| 过期快照或写入序号冲突 | 等正常刷新，核对实例、loaded revision/epoch/point seq，重开写入弹窗，不自动重试旧提交 |
| 数据库损坏/版本不兼容/只读/存储不足 | 保留原库和日志，停止继续操作并排查；不删除历史、改schema或用空库覆盖 |
| 日志观测降级 | “日志与存储”核lost/stdout/file丢失计数和配置库路径，保留原输出；日志不完整不能当成功证据 |

“日志与存储”点击 **刷新** 读取最新有界日志；事件筛选填写实际事件名，再 **筛选**，清空筛选恢复列表。分页每页50条，不是无限采样历史。时间字段为单调时钟ns，不是日期时间；技术长表在表内横滚。
