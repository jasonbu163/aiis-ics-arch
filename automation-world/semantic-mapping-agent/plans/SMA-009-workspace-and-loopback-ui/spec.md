## 3. P1 手工回环流程

### 3.1 页面结构和步骤

手工回环分为四个有清晰名称和状态的步骤，按需展示当前步骤的主操作。完成、当前和待处理步骤可辨识。允许返回先前步骤修正，不因切换步骤自动发送请求或自动保存配置。步骤的内容及进入条件在控件旁可见。

1. **选择来源。** 展示已保存连接、HTTP 是否允许、已选入的采集 GET 材料、PLC、DB 和点位。通过现有 options/latest 获得候选，能选择单点、多点或明确的全部点位，显示值、类型、质量与真实采集时间；`0`、`false` 和缺失状态可区分。GET 不发 POST。缺材料时说明并提供跳转 API 材料的入口；材料已选后回到回环保留未失效的用户输入。连接不可用、HTTP 关闭、列表为空、加载中、失败及超时分别给出状态和可执行的后续操作。事实表携带来源时只预填有效选择，仍须显示当前材料、PLC 和 DB。
2. **查询并选择样本。** 显示当前 PLC/DB 及上海时间的起止输入。缺任一前提时在查询按钮附近说明，如「先选择 PLC 和 DB」「请填写开始与结束时间」；输入缺失或无效的具体位置可见。按后端时间范围和分页合同查询，区分未查询、加载中、无结果、HTTP／业务失败及超时。结果行展示采集时间、点位数、样本标识和「使用此样本」操作；样本标识帮助核对，无需用户手工输入。点击后 GET 该行 `history/{id}`，展示同一次采集的详情及已选状态。返回历史列表再回来时，来源及筛选未变则保留已选样本和草稿。
3. **配置目标并映射。** 展示来源 PLC/DB、所选样本、点位数量及实际采集时间。选择已有登记的目标 PLC、DB、实例与来源代次，填写目标流未使用的十进制序号和点位映射。目标可为不同 external PLC，或同一 external PLC 的专用不同 DB；相同 PLC/DB 的源和目标不通过。序号不自动推测为可用，`409` 清楚反馈。点位映射保留类型、质量、值及原采集时间，不把不同历史样本拼成一次采样。配置保存使用现有 SQLite 版本检查和备份合同；失败或冲突时草稿保留。
4. **预览、推送和回读。** 配置有效且选定的 history 详情 GET 成功后，用户打开预览。预览显示源／目标 PLC 和 DB、目标实例／代次、序号、样本标识、点位数量、POST URL 以及请求 JSON。用户检查后显式点「测试推送」才 POST。可关闭预览或返回修改，此时不发 POST。收到匹配的 HTTP 与业务回执后显示成功并提供「回读目标样本」，通过现有 GET 按目标及样本标识展示点值与质量；回读未找到与请求失败可区分。

### 3.2 状态与异常

- 同一回环流程返回前一步，已选来源、历史时间、样本和目标草稿在仍有效时保留；切换选项、连接、样本、点位、序号或已保存配置产生变化时，关联的未发送预览立即失效并提示重新预览。旧 GET 的迟到响应不能覆盖当前选择。
- 正在发送时防止重复提交。成功必须核对 HTTP `200`、业务 `code=200`、`committed` 与 `created` 或 `duplicate`，并匹配目标 `contractVersion`、`instanceId`、`sampleId`。失败和结果未知给出不同状态；HTTP 错误、超时、身份冲突及点位缺失要能从界面看到。
- 超时、断连或回执不明时显示「结果未知」，提供查询目标历史的动作。当前会话保留原请求身份和字节时，可由用户明确重试同一请求；不能悄悄换新身份或自动推送。为避免丢失未知结果的对账依据，调整目标或关闭前提示会影响本次对账，允许先回读或返回。关闭应用后按原样本标识与目标历史人工核对。
- 步骤、弹窗和只读查询不能擅自创建来源、改变目标记录或发 POST。GET 成功或预览成功不自动触发发送。SMA 本机 SQLite 与备份仅存用户保存的连接、选择和映射等配置，不持久化采集值、样本正文、回执、提交身份或投递进度；本次结果只在会话中保留。
