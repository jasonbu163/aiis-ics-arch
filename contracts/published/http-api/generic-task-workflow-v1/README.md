# Generic Plan and Performance HTTP v1

[中文](README.zh-CN.md) · [OpenAPI extracted from the registered application](openapi.json) · [Approved specification](../../../../plans/ARCH-TASK-001-generic-plan-performance/spec.md)

This is the ARCH-TASK-001 r1 candidate source contract, not proof of deployment or field integration. The OpenAPI file contains the 16 task paths and referenced schemas extracted from normal `create_app(testing=True)` assembly. Success uses `code/message/data/timestamp`; failures use the matching HTTP status and a stable `task.*` `errorCode`. IDs and configuration revisions are decimal strings; observation sequences are JSON-safe integers; business timestamps include `+08:00`. Business field names and label language keys are preserved.

Logged-in operations use the existing `plan` and `performance` grants; only admin saves definitions. Supplementing a plan requires both grants. Anonymous integration is closed by default and may be enabled only at a trusted project boundary. `producerId` identifies and scopes the producer; it is not a credential. Configuration GET requires only `module` and optional `fieldConfigVersion`, and by-task GET requires only the path task number; a stored target must be registered. Network admission remains a project responsibility.

Set `TASK_INTEGRATION_PROFILE_FILE` to a private JSON file outside the repository; `TASK_INTEGRATION_ENABLED` controls the integration entrances separately from project mapping validation for logged-in plan creation. The [synthetic profile](examples/private-project-profile.json) shows MES and executor grants plus per-target, per-version dispatch fields, PLC sequence bound `plcSeqMax`, and one automatic source. Preserve the mapping, sequence bound and automatic producer for every version already in use. Register a new version for a changed stream, retain earlier versions in parallel, and load configuration through the approved process. This file is not an automatic archive of configuration history.

A newly migrated database begins with empty version 1 / revision 1. The two example saves publish v2 and v3; register v1–v4 in the target profile before this rehearsal. Version 3 contains all six sample fields; disabling shared field 03 for AC09 publishes v4. Always read the actual version and revision first, particularly if another administrator may have saved a change.

The [Chinese walkthrough](README.zh-CN.md#合成-ab-走法) gives the executable sequence and curl forms. It creates B then A, claims A first, reports matching request/ack sequences 41 and 42, submits A12, B1 and A13, preserves manual true/false and tests late, duplicate, conflicting and completed reports. Two separate runs exercise supplement with backfill disabled and enabled. Copy examples to a temporary directory, replace `RUN`, version and returned dispatch IDs consistently, and use synthetic Shanghai timestamps. No example authorizes writes to a real database or device.

Frontend pages read their own API and each task's bound definitions; widths and unsaved drafts are local preferences. FastAPI owns plan, performance, dispatch and action records, committing an accepted snapshot and allowed plan feedback together. MES submits orders; CA/FF owns the PLC handshake, locally retained request/ack and batch report; DAA retains acquisition facts; SMA transforms those facts into complete per-task/version snapshots. The backend neither polls PLCs nor supplies the agents' local persistence and restart reconciliation.

PLC addresses, field widths and handshake details, isolation of old executors, SMA sequence recovery and retention/release of final samples remain site integration work. The historical [business-integration-v1](../business-integration-v1/README.md) keeps its original schemas and evidence: its four performance anonymous operations retire under this task, while the four equipment/monitor operations, independent quality and PLC facts v2 remain under their own contracts.
