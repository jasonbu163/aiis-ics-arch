# 共享字段管理列表与原子批量删除 r1

## 1. 目标、背景和状态

计划与实绩的「共享字段管理」入口目前共用一个页面和一份共享字段配置。页面直接以可编辑表格显示全部设置，字段增多后不利于定位，也缺少逐项编辑、勾选后的批量编辑与原子批量删除。Human Owner 已审阅会话预览，确认采用主表、单项编辑和批量编辑弹窗的方向，并提出底部分页。预览使用示例数据，其预先标识可否删除的模拟状态不代表实际 API 能提供此信息。

本 r1 规定主表筛选、客户端分页、逐项和多项编辑，以及新增单次提交、整批成功或失败的共享字段删除接口。字段读取、编辑和单项删除沿用现有接口；批量删除新增接口并保留现有保护。数据库表结构和持久模型不需变更，现有业务配置版本和使用证据继续使用。

[ARCH-TASK-001 r3](../ARCH-TASK-001-generic-plan-performance/spec.md) 的 QA6 已通过，Human Owner 最终验收待定。它与本任务相关，各自保持独立的范围、证据及最终验收。本规格不会更改旧任务状态，也不声称已完成本任务实现或验证。

Human Owner 已批准 `ARCH-TASK-002 r1` 的精确开发范围。下一 gate 为 Development 创建本任务 `tasks.md`、实施并自检；实际 `developer_handoff` 后由 fresh-context Verification 创建 `checklist.md` 独立验证，再由 Human Owner 决定最终验收。范围批准不自动授权对既有 dev、生产或现场数据执行写入、服务切换和发布。

## 2. 当前依据

1. [共享字段入口](../../frontend-js/src/app/plan/views/shared-fields/index.vue)由计划和实绩两个菜单共用。它以当前模块 `plan` 或 `performance` 调用 `GET /api/v1/task-field-configs?module=...`，从返回定义筛出 `scope=shared_sync`。GET 的模块参数仍只有 `plan` 和 `performance`，返回相应模块本地定义和共享定义，含停用字段。页面和配置写入均受现有管理员边界约束。
2. [现有设置编辑器](../../frontend-js/src/app/plan/components/TaskFieldEditor.vue)也供两个列表各自的本地字段弹窗使用。现有 `PUT /api/v1/task-field-configs` 接受 `module=shared`、`configRevision` 和多个 `changes`，可一次保存一个或多个共享字段。已保存字段的稳定键、槽位、类型和单位不可直接改变。
3. [现有单项删除](../../backend/app/task/services/async_fields.py)以 `scope`、`slotNo`、`name` 与 `configRevision` 校验当前身份、历史版本完整性及计划、实绩、历史下发批次等使用证据。受保护或证据不完整时保守拒绝。当前 GET 不提供可删除标识；未知的外部映射也不能由该 GET 证明已检查。
4. 现行事务先锁定字段配置单例，再读取/锁定当前定义。业务任务写入和配置发布使用同一首锁。正常保存时，仅展示名称、可见性或顺序有变化只推进 `configRevision`；新增、删除及业务设置变化发布新 `configVersion` 并推进 `configRevision`；无实际变化二者均不变。
5. 单项删除接口及任务错误信封已存在。提交结果不明使用 `503 task.commit_unknown`。它不同于已知提交前校验失败，客户端需重新读取当前配置后核对，不能把响应丢失解释为必然失败。

## 3. 范围与界面要求

### R01 两个入口和主表

- 保留 `plan/shared-fields` 与 `performance/shared-fields` 的路由、菜单和管理员权限。两个入口访问同一组 `shared_sync` 定义；从任一入口成功修改后，另一入口重新读取应呈现同一结果。
- 主卡第一栏包括「共享字段管理」、可悬停和键盘聚焦的帮助、字段版本和配置修订号，以及「新增字段」「重置列宽」「刷新」。帮助说明共享范围、字段设置与历史保护，删除前仍提示核对外部 MES/SMA 等引用。版本和修订号是只读事实，不由用户编辑。
- 第二栏提供字段搜索、启用状态和实绩归属筛选，以及查询和重置。搜索覆盖稳定字段键、中英文名称，大小写不敏感；筛选在当前共享字段集合上执行。读取失败显示错误及可重试入口，不把旧缓存伪装成已刷新数据。
- 第三栏以一行一字段的只读表格展示选择框、稳定字段键、中英文名称、槽位、类型与单位、实绩归属、启用状态和行内「编辑」「删除」。显示真实 API 返回的字段；计划与实绩可见/可编辑、回写、顺序等完整设置在编辑弹窗展示。空列表和筛选无结果均有明确空状态。
- 顶部提供勾选数量、「批量编辑」「批量删除」，未选中时不可执行。行内操作作用于该行，批量操作只作用于当前明确勾选的字段。

### R02 分页、选择和列宽

- 一次读取共享配置，先在客户端筛选，再按槽位升序分页；默认每页 20 条，提供 10、20、50、100 条页大小及总条数、页码切换。每组共享槽位上限为 100。末页删除或筛选后若页码越界，回到有效末页。
- 表头选择框仅全选或取消当前页，翻页及更改每页条数保留其他页已勾选项；已选数量包含所有页。执行查询或重置筛选时清空选择并回到第一页。刷新成功且修订号未变时，按完整身份 `scope + slotNo + name` 保留仍存在的选择；修订号变化时清空选择并提示重新选择，避免选择已被其他人修改或重建的字段。刷新失败保留已有显示及选择，并提示失败。
- 主表普通业务列及批量编辑表普通数据列可拖拽、设最小宽度、必要时横向滚动。选择和操作列可固定。列宽通过现有公共列宽工具按应用、表和稳定列标识本机保存，翻页、筛选、刷新、页面切换及重载后恢复。两张表的偏好隔离；不写入业务配置。每张表提供「重置列宽」，提示为「恢复默认列宽」，只重置对应表且不清空编辑草稿。旧偏好能安全沿用时沿用，失效列回退默认。
- 参考会话预览的布局和信息层级，中英文、浅色和深色主题、桌面及窄屏可用。窄屏内容和按钮不重叠，宽表局部横向滚动。可通过键盘使用帮助、筛选、选择、弹窗、确认和列宽重置。

### R03 新增、单项编辑和批量编辑

- 「新增字段」打开单字段弹窗。按现有范围、槽位、名称、类型、单位、双语名称和各适用设置校验，成功通过现有 PUT 增加共享字段。保存前仍属草稿，取消或关闭不写入。
- 行内「编辑」打开单字段弹窗，只编辑该字段。稳定键、槽位、类型、单位对于已保存字段保持只读。保存只提交该字段实际变化。
- 勾选后打开「批量编辑」弹窗，以可横向滚动的现有字段设置表形式逐行编辑**所选字段**。完整展示中英文名称、启用、可清空、实绩归属、回写、计划/实绩可见与可编辑以及列顺序。已保存字段的稳定键、槽位、类型和单位只读。跨页选择全部进入同一个弹窗，未选字段不提交。
- 归属、回写、实绩可编辑及其他适用性沿用后端现有校验，订单快照不可回写，非人工归属不可勾选实绩可编辑。空顺序表示按现有槽位规则，明确修改为 `null` 与未修改须区分。批量编辑为逐行草稿，并非把一个值强行覆盖到所有选择项。
- 点击保存后，将实际有变化的所选共享字段合并为一个 `module=shared`、当前 `configRevision` 的 PUT `changes`。单项编辑只包含相应字段，批量编辑不得提交未勾选行。无变化时版本和修订保持，客户端可直接关闭或提示无变化。
- 发生校验错误、权限错误或修订冲突时，保留弹窗和草稿并显示原因。冲突后用户可先记录草稿，再自行取消或关闭并刷新权威配置后重试；不得静默覆盖他人的新配置。主动取消或关闭弹窗丢弃未保存草稿。既有计划本地字段及实绩本地字段弹窗的范围、保存、删除和草稿行为继续有效。
- 新增或编辑的提交结果不明时，同样禁止自动重放。保留当前草稿并提示结果未明，读取权威配置及修订供用户核对；不得以读取结果自动覆盖草稿或推断该请求必然成功。用户确认后自行取消草稿、刷新并决定是否重新编辑。

### R04 删除和失败处理

- 单项删除继续使用现有 `POST /api/v1/task-field-configs/delete`，在行操作后显示二次确认并明确字段身份。确认前不写入。
- 批量删除对跨页全部勾选项展示确认数量和完整身份，确认前不写入。使用第 4 节一次请求提交所有选中共享字段；任一字段不存在、身份改变、已被使用或使用证据不足，或者修订冲突时整批不生效，其他候选不先行删除。
- 实际 GET 不提供使用资格。确认界面不得声称任一字段已经可删或列出未经后端核实的保护状态。若后端拒绝，显示已知的具体字段和原因，保留当前选择，允许用户调整后重新确认；全局历史证据错误不臆测到某一个字段。允许每次只返回并说明首个可定位的阻塞项。
- 请求发出后暂时禁用重复确认。明确的提交前校验拒绝不改变配置，界面展示相应错误并保留可操作状态。对网络中断或 `task.commit_unknown`，保留待核对的身份，提示结果未明，重新读取权威共享列表、配置版本及修订号，显示当前字段是否仍存在；不自动原样重放，不把读取结果推断成该请求必然成功或失败。用户核对当前状态后可重新选择、再次确认。后端事务保证一个请求不会部分删除。
- 批量或单项删除成功后更新列表、版本、修订及选择；字段读取和删除不更改既有计划/实绩值、历史配置或使用证据。确认为未使用而删除的槽位可按既有规则重新使用。

## 4. 新增原子批量删除 HTTP 合同

路径相对 `/api/v1`。

### 请求

`POST /task-field-configs/batch-delete`，使用现有登录管理员认证与 task 错误/响应信封。请求只支持共享字段：

```json
{
  "configRevision": "14",
  "fields": [
    { "scope": "shared_sync", "slotNo": 4, "name": "operatorNote" },
    { "scope": "shared_sync", "slotNo": 5, "name": "qualityFlag" }
  ]
}
```

- `configRevision` 为现有正整数十进制字符串；`fields` 含 1–100 项。每项仅接受 `scope=shared_sync`、1–100 的整数 `slotNo` 和现有稳定字段键格式的 `name`。字段身份缺失、额外键、错误类型、空数组、超过上限、重复槽位或重复身份返回 `422 task.invalid_request`，不执行删除。
- 一个共享槽位只能在请求中出现一次。后端依据当前配置确认每个三元组完整匹配，不能以槽位或名称单独猜测身份。请求顺序定义后续定位索引和成功响应的 `deleted` 顺序。

### 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "outcome": "deleted",
    "deleted": [
      { "scope": "shared_sync", "slotNo": 4, "name": "operatorNote" },
      { "scope": "shared_sync", "slotNo": 5, "name": "qualityFlag" }
    ],
    "configVersion": 15,
    "configRevision": "15"
  },
  "timestamp": 1795170000000
}
```

这是两项合成示例，版本以请求时实际状态和返回结果为准。成功对整批发布一次完整字段定义快照，`configVersion` 和 `configRevision` 各增加一次，记录有界管理员审计事件。保留既有配置及历史快照完整性，释放已删除的当前槽位；不更改计划、实绩、历史批次及使用证据。

### 拒绝和未知结果

- `401 task.unauthenticated`、`403 task.forbidden` 沿用当前认证授权；非管理员和未认证调用不得产生写入。
- 修订过期返回 `409 task.config_revision_conflict`。当前字段身份不存在或不匹配返回 `404 task.not_found`。字段已有使用或证据不足返回 `409 task.field_in_use`。
- 延续现有 `ErrorEnvelope`，其 `details` 只含字符串字段。可定位到某个请求项时，`details.field` 为零基索引路径，例如 `fields.1.name`，`details.reason` 使用现有相关原因码；只需返回按请求顺序遇到的首个阻塞项。版本表不连续等全局证据问题可将 `details.field` 设为 `fields` 并返回对应原因，不声称某个具体字段可删。
- 校验、保护和已知提交前失败时，全部定义、槽位、快照、`configVersion` 和 `configRevision` 均保持。事务提交结果不明返回 `503 task.commit_unknown`，查询核对逻辑按 R04 执行；其他不可用错误沿用 `task.unavailable`。任何单一事务提交只有整批提交或整批不提交的状态。
- 不新增资格预检查接口。现有单项删除路径、所有原作用域、错误语义和调用方继续兼容。

### 事务和并发

复用现有单字段保护语义和同一数据库事务，先获取配置单例写锁，再按现有锁序读取定义及所需历史和使用证据；在该边界内检查一次期望修订、逐项身份和每项保护，全部通过后才构造一次新快照并提交一次。不能通过循环调用单项 HTTP 接口或逐项提交实现批量删除。与计划/实绩写入、单项删除和配置保存竞争时，结果须等价于某个串行提交顺序。任何内部错误、校验失败或提交前注入故障都不能留下部分删除、部分新快照或额外版本。

## 6. 风险与恢复

- **事务和证据风险。** 批量检查必须对每一项执行与单项相同的保守保护，测试历史定义不连续、用过但无值/停用、缺少使用证据及并发写入。未知外部映射无法由本系统全量发现，确认提示需保留人工核对。
- **并发修订与未知提交。** stale revision、对象消失、业务写入竞争及 commit unknown 都可能发生。UI 保留草稿或选择，并按 R03/R04 核对，不能自动重放造成误导。
- **共享编辑器复用。** 当前本地字段弹窗依赖同一组件。若复用或拆分组件，分别回归计划本地、实绩本地及两个共享入口，避免波及权限、草稿及现有列宽偏好。
- **历史可见性限制。** ARCH-TASK-001 QA6 已记录，对事后被选择性破坏且无可观察状态差异的唯一使用证据，现有模型无法识别。r1 继承该已知能力边界，不宣称能恢复不可观测事实或证明所有外部引用已检查。
