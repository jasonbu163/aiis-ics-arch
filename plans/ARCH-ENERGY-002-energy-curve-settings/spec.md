# 能耗曲线设置 · r1

## 1. 目标和依据

在「能耗管理 → 配置管理」保存能耗曲线组，管理员选择表计、采样组及已有能耗指标。用户在「能耗统计」选择曲线组和时间，查看配置好的曲线和指标汇总。页面风格、曲线编辑行和图表交互参照现有过程监控，使用能耗自己的配置与样本。

Human Owner 于 2026-11-25（Asia/Shanghai）确认 [v5 交互原型](../../work/energy-curves-pricing-review-v5.html)，并明确说「确认 v5 原型，批准按 STD 修订单价规格并起草能耗曲线设置、公有 GET 规格，先不启动开发」。Human Owner 已批准本文件的精确 r1 开发范围，按 STD 进入 Development。原型使用合成数据；其中的数值计算仅供界面演示，实际汇总继续使用后端既有统计合同。

当前能耗统计页用表计、采样组、指标和时间筛选，经 `options`、`definitions`、`samples`、`summary` 获取数据，按物理量及单位自动分图，并复用过程 [CurveChart](../../frontend-js/src/app/monitor/components/observations/CurveChart.vue)。过程 [曲线设置页](../../frontend-js/src/app/monitor/views/observations/admin.vue)提供曲线组、排序、启停、实线与虚线。能耗当前尚无持久化曲线组。[ARCH-OBS-007](../ARCH-OBS-007-energy-management/spec.md)、[ARCH-OBS-009](../ARCH-OBS-009-energy-ui-followup/spec.md) 和 [ARCH-OBS-010](../ARCH-OBS-010-energy-registered-batch-ingest/spec.md) 已有范围与验收继续作为原能力依据。

## 2. 领域与范围

1. 一条能耗曲线组配置对应**一块表计、一个采样组、一张曲线图**。每条曲线引用这块表、这个组的一项能耗指标。第一版不做跨表或跨采样组同图。每个表计可以建立多个曲线组。
2. 能耗曲线配置、指标、样本和回执属于能耗域。复用实时／过程的组件和交互，不引用设备状态或过程的曲线配置、来源登记、样本、回执或任务号，不建立跨域外键、JOIN 或任务号存在性依赖。联合业务由调用方分别读取并处理。
3. 现有的能耗多表免 Token POST、单表 Bearer v2、表计指标、样本管理及价格接口按其原合同使用。曲线保存、选组和查询不修改已有样本、质量、时间、登记或价格。
4. 曲线组管理与统计页读取均使用登录用户 Bearer。管理员维护曲线组时沿用现有管理员检查及管理员可访问表计范围。统计用户需要现有 `energy-consumption-read` 权限，曲线组和其样本仅允许访问该角色可读表计；页面可见不增加后端权限。
5. 单价项目与公有 GET 各有独立规格，本任务不开发单价、免 Token GET、SMA／CA／FF 客户端、费用计算或流程联动。

## 3. 配置管理

1. 在「能耗管理 → 配置管理」保留现有上卡与「表计指标配置」「写入登记」，增加「曲线设置」选项。与单价项目配置共用上卡时协调两项变更，不覆盖已有选项。
2. 下卡参照过程监控，提供表计和关键词筛选、查询、重置、新增、编辑及重置列宽。列表显示曲线组键、标题、表计、采样组、指标及线型、排序和启停状态。支持空配置、无匹配、加载及失败状态，失败后可重试。普通列使用公共列宽组件并按稳定字段保存本机偏好，表格不足宽时横向滚动。
3. 新增／编辑弹窗采用项目公共紧凑三段式布局。内容分为「基本信息」「数据范围」「曲线」「显示设置」。基本信息为稳定曲线组键及中英文标题。至少填写一个标题，缺失语言回退显示已填写的标题。数据范围选择已配置、当前管理员可访问的表计和该表的采样组。曲线区可添加、移除、调整顺序，选择该表和组的已有数值指标与实线／虚线。显示设置包含排序和组启停。单条曲线启停沿用过程曲线编辑方式；只有启用的曲线参与展示。
4. 曲线组键创建后不可更改且全局唯一。同一组内一项指标出现一次；同图启用的曲线具有相同 `quantityKey` 和 `unit`，缺省单位彼此相同亦可配置，显示与统计沿用原指标语义。至少有一条启用曲线。按现有合同校验表计、采样组、指标与数据类型，不按能源名称、采集年龄或数值大小另设规则。
5. 指标写入状态与历史展示分开。已存在的能耗指标可用于曲线，指标停用后既有样本仍可查看，显示配置不改变指标的写入状态。若表计或指标后来被移出当前可访问范围、配置缺失或物理量／单位不再一致，统计页给出可理解的配置不可用状态，管理员可编辑恢复；不得把不同单位强行画在同一图上，也不更改历史样本。配置页保留原引用供管理员排查。
6. 标题、正文、页脚对齐，超长时正文独立滚动；新增／编辑的页脚为取消和保存。点击遮罩等同取消，不提交。中英文和明暗主题遵守项目组件与 i18n 规则。

## 4. 能耗统计页

1. 主卡继续采用与过程曲线一致的布局。增加「曲线组」选择，提供「按表计查询」以及当前用户可读表计下已启用的曲线组。选择曲线组后，其表计、采样组和曲线来自保存的配置。用户选择时间后查询；切换有效配置时若已有有效时间范围，立即按新选择查询。可使用刷新、查询和恢复默认。
2. **原有手动模式保留。** 「按表计查询」继续提供表计、采样组、指标和时间范围，使用现有自动按物理量／单位分图和指标汇总；无任何曲线组时也能完整使用。恢复默认回到手动模式并沿用现有默认值和时间输入行为。不可因曲线配置读取失败而使手动样本查询永久不可用，失败时提示并允许重试。
3. 选中的已配置曲线组按数组顺序展示启用曲线，名称、单位和小数位取能耗指标配置，线型取该组设置。样本按原表计、采样组和 `observedAt` 查询并送入共享 `CurveChart`。曲线采用真实采集时间，保留组件的图例、缩放、样式、缺测断点和同时间样本交互。某样本未传该指标就是缺测，不继承前次值；`0` 是有效数值。
4. **汇总选择。** v5 原型展示第一条曲线的汇总，r1 选择该组第一条启用且有效的曲线为汇总指标，并在汇总旁显示指标名称。继续调用原 `summary` 接口并显示 `latest`、`amount`、状态与原因，包含质量、区间、缺口和不完整语义。无法统计时显示后端结果，不用前端简单相减或补零。切换线条可见性不改变汇总指标；修改配置顺序后按新的第一条启用线生效。
5. 空表计、无曲线组、无指标、所选时间无样本、无可绘制值、部分缺测、配置不可用及读取失败分别清楚显示。选择／刷新／重试／页面离开时，较旧请求不能覆盖当前选择。读取全部分页时保持原样本 API 的权限、时间范围和分页语义。

## 5. API 合同

均以 `/api/v1` 为前缀，使用既有 `{code, message, data}` 信封。路径和字段是本 r1 合同。只增加能耗命名空间接口，具体响应与其他观测接口保持一致。

| 方法及路径 | 权限与行为 |
| --- | --- |
| `GET /energy/curve-configs?meterId=...` | 管理员读取其可访问表计的曲线组，含停用组，可选表计筛选，按 `sortOrder, curveGroupKey` 升序。 |
| `POST /energy/curve-configs` | 管理员新增曲线组，返回保存后的完整配置。 |
| `PATCH /energy/curve-configs/{curveGroupKey}` | 管理员更新标题、表计／采样组、曲线、排序或启停。曲线组键不变，提交部分字段时其余字段保留。 |
| `GET /energy/consumption/curve-configs?meterId=...` | 持 `energy-consumption-read` 的登录用户读取其表计范围内已启用的曲线组，可选表计筛选，排序与管理列表一致。 |

管理读取不传 `meterId` 时仅返回管理员可访问范围内的组，统计读取不传 `meterId` 时仅返回登录用户可读范围内的启用组。显式请求不可访问表计返回既有 403，未登录或令牌无效返回 401。未知组更新 404，重复组键 409，字段、指标引用或曲线单位非法返回既有稳定错误信封 422。空列表是正常 200；数据库不可用或实际结构不兼容使用既有清晰错误。读接口返回配置本身，不携带样本值。

新增请求与响应的 `data` 使用以下形状，组内顺序即显示顺序：

```json
{
  "curveGroupKey": "meter01-power",
  "titleZh": "1号电表功率",
  "titleEn": "Meter 01 power",
  "meterId": "meter-01",
  "groupKey": "electricity",
  "sortOrder": 10,
  "enabled": true,
  "series": [
    {"metricKey": "phaseAPower", "enabled": true, "lineStyle": "solid"},
    {"metricKey": "phaseBPower", "enabled": true, "lineStyle": "dashed"}
  ]
}
```

示例指标仅用于说明；实际保存以目标表计指标配置为准。列表 GET 的 `data` 为上述对象数组，POST／PATCH 的 `data` 为一个对象。统计页继续使用 `GET /energy/consumption/options`、`/definitions`、`/samples` 和 `/summary`，没有新增用于能耗与过程关联的接口。示例及发布合同须与实际 OpenAPI 一致。

## 6. 数据结构、迁移和回退

通过显式 Alembic 后继新增 `energy_curve_group_configs`。每行以 `curve_group_key` 为稳定主键，保存 `title_zh`、`title_en`、`meter_id`、`group_key`、`enabled`、`sort_order` 及有序 `series` JSON；系列保存 `metricKey`、`enabled`、`lineStyle`。表计和指标解析使用已有能耗配置。新增表只存配置，历史曲线点仍从 `energy_consumption_main` 和 `energy_metric_configs` 读取。新增表不依赖设备状态或过程表。

迁移不向真实库写入示例配置。实际前驱以实施时唯一 Alembic head 为准，与 `ARCH-ENERGY-001` 等并行结构变更顺序协调，不修改历史迁移；迁移前后核对原能耗样本、指标、登记和回执及过程／设备记录。迁移后新增配置表为空时，手动模式继续可用。无关迁移推进全库 revision 时，能耗曲线与已有能耗读写按实际依赖继续工作，不要求修改 profile 或把固定全库 revision 当运行门槛。目标库身份、现有权限和业务校验仍生效。

回退应用前保留新增曲线配置，回退不会删除能耗样本和回执；涉及删除新增表或实际历史数据调整须有单独核对与授权。合成环境验证迁移、升级中断和后继兼容。实际 dev／生产备份、迁移及服务切换属于独立授权，批准本规格开发不等于批准这些动作。
