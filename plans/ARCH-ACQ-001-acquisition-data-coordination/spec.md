# 采集数据优化与业务接线项目路线

## 1. 目标与范围

这是项目根级任务路线。先简化 PLC 原始样本从 DAA 到后端的链路，再提供 Web 原值查询，最后按调用方证据清退旧 Projection。根路线统一追踪这四项的顺序、交接凭证和剩余风险，并核对两条业务线能否接收 SMA 的最终映射结果。四项各有独立规格、批准与验收，通过任务引用和前置条件关联。

采集数据优化会话负责本轮一大四小规格起草，后续继续协调第 1、3、4 项。根路线由 Human Owner 主动交接至「总-评估项目进度与设计路线」，该会话作为根路线唯一后续人工跟踪入口。由 Human Owner 本人主动触发各任务进度和完成核对，总评估会话据权威记录汇总。各会话链接供人工定位，各项实施和运行权限以各自获批范围为准。 [总-评估项目进度与设计路线](codex://threads/01a1a441-38ff-7942-9d15-13537a819355)

采集侧按 PLC、DB 和原采集时间组织事实。设备实时状态、`monitor` 过程监控及任务与实绩属于业务侧，按各自的设备、任务和指标规则处理。事实侧的样本历史与逐点最新值两张表，和 ARCH-OBS-001 规划的业务实时快照与过程历史两张表，各有存储口径。事实原值按原采集时刻起最多保留三个上海自然月，补传沿用原截止时间。已入库的业务历史按业务规则永久留存。

**根任务的交付面**限于本目录的分阶段角色文档，以及协调者机械同步根 `PLAN.md`、`PLAN.zh-CN.md` 和 `plans/README.*` 的对应索引行。各实施规格及对应模块索引按所属任务单独维护。业务设计与实现、SMA 接线实施、真实环境切换、旧表与旧数据处置、Docker 操作、数据库迁移执行、现场设备操作和发布各走独立授权。

既有的 BE-009 事实 provider、BE-010 业务集成和 DAA-008 旧合同联调作为背景基线。B-RUN-01 的专用环境及留档状态以原任务记录和实际交接为准。新版的合同版本、验证结果和采用决定单独核对。 [BE-009 验收](../ARCH-BE-009-backend-facts-integration/checklist.md) · [BE-010 验收](../ARCH-BE-010-anonymous-business-integration/checklist.md) · [DAA-008 执行记录](../../automation-world/data-acquisition-agent/plans/DAA-008-reliable-facts-upload/tasks.md)

## 4. 统筹要求

- **R01 由 Human Owner 主动发起复核。** Human Owner 在总评估会话发起阶段、交接或完成核对后，该会话读取各工作线当前角色文档与对应候选，必要时只读查相关会话。在获准的根角色文档中汇总复核时间、任务与 Revision、工作树或提交、当前阶段、证据链接、下一步和负责人。任务完成依据对应候选的独立核验和 Human Owner 验收记录。会话状态仅用于定位，证据不足时登记缺项和下一门槛。根 PLAN 只保留摘要与入口。
- **R02 守住后端先行。** 后端交接必须带版本化请求与回执契约、观察时间与采样次序定义、鉴权与拒绝口径，以及重复、响应丢失后重试、迟到与保留期的受控验证。阶段记录缺少任一必需证据时，列出缺项和解除条件，DAA 保持待移交。
- **R03 对齐一个写入口。** r1 按一个写入接口和逐样本确认起草，DAA 可在本地分别调度实时与补传。若另一路讨论最终决定拆入口或批量协议，先协调两个规格的合同和验收口径，经 Human Owner 精确批准新 Revision 后实施。
- **R04 核对退役责任。** 每个旧入口列出调用方、使用语义、替代或兼容路径以及验证证据。使用方不明或仍有旧 writer 时，只交付经证明可以退出的范围，其余登记负责人、证据缺口及实际切换门槛。业务 API 继续按原归属交付。
- **R05 按角色分层。** 根规格及各执行任务分别遵循 STD。批准、`developer_handoff`、独立 QA、Owner 最终验收和运行采用逐项核对。重大范围、依赖或验收变化交所属 PM 修订，相关工作暂停在未满足的门槛。统筹通过文档与阶段复核持续进行。

后续角色按范围选用 `aiis` 与 `project-governance`。后端与公开合同由 ARCH-BE-012 路由 `backend-arch`，DAA 由 DAA-010 路由 `rust-runtime` 及适用的 `desktop-tauri`，Web 由 ARCH-FE-005 路由 `frontend-ui` 与 `i18n-workflow`，旧入口核对由 ARCH-ACQ-002 路由 `interface-lineage-audit` 及受影响端的技能。每条工作线的技术验证归自己的证据记录。

## 5. 风险、回退与待决策

| 事项 | 处理口径 |
| --- | --- |
| 是否需要逐份按提交顺序回放 | r1 拟以两张值表为基线。若 SMA 将来必须按提交顺序回放启用前的每份样本，ARCH-BE-012 定版前要确认从新版首份样本记录发布序号，并评审单行发布状态表和游标边界。若启用前只需按时间回查，后续可在 SMA 启用点独立批准顺序消费扩展，从该启用点开始编号，更早的样本在保留期内按原采集时间查询。 |
| 断网补传或新旧合同不一致 | 保留 SQLite 原有配置、样本和待确认记录。停止使用不匹配的接口，按双方已批准合同修复后恢复。原合同的批准、失败、隔离联调和回执证据继续按原任务留档。 |
| 清退造成旧业务失去写入方 | 先核对调用方和实际 writer，明确替代链路与业务结果对账。切换和回退需按受影响环境独立批准。旧表、历史数据、备份和导出另行决定。 |
| 两条业务线或 SMA 延后 | 采集四项按自身批准范围验收，并将依赖未就绪和过渡路径列为后续事项。缺少任一业务目标的接入证据时，完整闭环保持待验证。 |

## 6. 验收标准

| 编号 | 根级复核标准 |
| --- | --- |
| AC01 路线可追溯 | 根路线、四份独立实施规格及所属索引互相可定位。通过总评估会话中 Human Owner 主动发起的复核记录，抽查各工作线 Revision、阶段、范围和下一门槛与权威记录相符。两条业务线各有会话与仓库依据。 |
| AC02 交接顺序 | 以实际记录验证第 2 项移交时间晚于第 1 项同范围独立 QA 与 Owner 验收，能用交接材料复现受控 provider。新版单入口合同两端一致。Web 验收能追溯经新版上报的样本和独立读授权。 |
| AC03 清退范围与残留 | 能逐项指出撤下的旧入口、回归证据及剩余调用方。仍在用的兼容写入路径有切换门槛。源码候选、实际运行停用及数据处置分别记录。 |
| AC04 采集交付检查点 | 四项各有经独立验证和 Owner 验收的实际交付范围。若第 4 项仅交付经批准的安全清退子范围，根记录明确已交付项和仍待切换项。 |
| AC05 完整业务闭环 | 两条业务线的接口版本及验收可定位，SMA 自有任务完成验收。同一受控样本可从事实与 Web 查询追溯至正确业务记录，重试和迟到场景的业务结果可核对。任何仍服务真实业务的旧 writer 有明确去向。此结果独立于采集交付检查点。 |

Human Owner 在总评估会话主动发起根路线完成核对。该会话定位各任务的独立证据和验收范围，按 STD 转交根任务独立 Verification 核对，记录已完成、待切换和待验证的实际范围。若只达到采集交付检查点，根索引标明完整闭环待验证。Human Owner 对经独立核验的精确候选作最终验收。运行采用另按获批范围判断。
