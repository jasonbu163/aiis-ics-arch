# 计划和实绩详情与字段弹窗 r1

Human Owner 已审阅并确认会话中的可交互弹窗预览，要求先修复计划列表和实绩列表详情「旧请求覆盖新请求」的问题，再统一详情、共享字段和本地字段的单项弹窗；此次只调整这些弹窗，不调整承载它们的其他界面组件。Human Owner 已批准精确 **r1**，交 Development 按本规格实施并自检。

## 2. 包含范围与优先级

1. **高优先级：详情并发和生命周期。** 计划、实绩的详情读取、对应字段配置、实绩可选的补建配置和既有保存结果，只能更新属于该次操作的有效界面。
2. **详情弹窗。** 两个列表的「详情」按已确认预览呈现只读详情、按权限进入编辑，以及实绩符合既有条件时进入补建；沿用真实字段、接口及写入规则。
3. **字段单项弹窗。** 计划和实绩的共享字段入口、本地字段入口共四条路径，统一「新增字段」、单行「编辑」、单行「删除确认」弹窗。依共享、计划本地、实绩本地显示对应设置。
4. **不在范围。** 主卡、表格、操作列按钮本身、筛选、分页、列宽、侧栏、路由、页面标题和其他页面组件均不调整。批量编辑表和批量删除确认的布局、交互、选择及请求语义不改；若单项与批量共用对话框，样式仅作用于单项模式，并验证批量不受影响。新建计划弹窗的内容和流程不重新设计；补建表单的字段、默认值与流程不重新设计，只允许其沿用详情弹窗必要的局部外壳和请求归属保护。

## 3. 详情请求归属与操作安全

### R01 最新打开意图

- 两个模块分别以用户最后一次打开意图为准，绑定具体记录和对应的字段配置。A 后 B，只有 B 的记录、配置、标题、表单、权限和加载状态可以进入 B；A 后续成功或失败不能覆盖 B、关闭 B、显示 A 的错误或提示、结束 B 的加载状态，亦不能使 B 可编辑字段发生变化。A 请求无需一定取消，但过期结果必须无副作用。
- 主记录和本模块配置必须属于同一有效意图。发起详情时在详情弹窗显示目标身份和加载状态，允许关闭；加载时不把上一条记录当成当前记录展示或允许操作。最新主记录或必要配置失败时，在弹窗给出对应失败状态与重试或关闭入口，不残留可误操作的旧数据。请求重试同样受最新意图约束。
- 实绩满足既有条件时，供补建使用的计划配置属于同一条实绩及同一打开意图。补建配置尚未就绪时不使用旧配置开放补建；其失败不遮挡已成功读取的当前实绩详情，补建入口保持不可用或隐藏。无论补建配置成功还是失败，过期结果不得改变新记录的配置、入口、错误提示或打开状态。
- 点关闭、Escape、路由切换/离开、组件卸载、快速关闭后重开，或切换到共用此对话框的「新建计划」，都要使相关旧详情请求失效。反向切换时，新建计划未完成的旧配置请求也不得覆盖较新的详情意图。关闭动画的 `closed` 等延后回调必须绑定原对话框生命周期，不能清空已经重新打开的新记录、表单或状态。
- 保存时沿用现有接口、差量构造和服务端结果语义，不自动重放。保存进行中防止同一草稿重复提交；若关闭、离开或打开意图发生变化，原保存的成功、失败与收尾不能关闭新弹窗、污染新草稿、显示旧错误/成功提示或重置新操作的 loading。必要时可在保存期间锁住当前弹窗内的重复操作，但不得把已发出的写请求描述为已取消或保证未提交。

### R02 现有权限和数据语义

- 详情默认只读。标题区在现有权限允许时提供「编辑」；无写权限用户不获得编辑入口。实绩的「补建计划」继续要求既有管理员/主管、计划列表访问权限、该实绩无同号计划且计划字段配置可用等条件，不能仅以只读样式替代权限判断。
- 编辑时继承现有 `canEditOrders`、`canEditRemark`、`fieldEditable`、`isNullable` 等逐项规则：计划管理员/主管按原条件编辑；实绩备注及人工归属、可编辑字段继续按现有角色规则开放；只读用户、自动或不允许编辑的字段不能通过界面获取写权。已有目标不可通过本次改造解除既有限制；空目标、清空、布尔值、数值及未修改字段的差量规则保持现状。新增计划、补建权限及 `backfillExisting` 默认值/提交含义保持现状。
- 保留真实接口返回的所有现有详情信息及启用的动态业务字段、单位、备注和模块差异。每个字段在只读详情中出现一次；缺失值显示缺失，不能把 `0`、`false` 或已有值误当作缺失。计划的优先级、实绩的有无计划及最近观测/开始/完成时间等，按原数据与字段含义显示，不凭示例编造。
- 时间仅作现有业务时间显示：上海时区、24 小时 `YYYY-MM-DD HH:mm:ss`，使用项目已有统一口径，不以刷新时刻替代业务事实，不修改 API、存储值或历史数据。若核对发现须修改后端、合同或迁移才能满足该口径，停止扩大范围并交 PM 处理。
- 取消编辑回到当前记录只读详情且不发送写请求。保存成功继续现有关闭弹窗、刷新列表的结果；预览中保存后留在详情仅为演示，不改变现有保存完成流程。补建原有提交、结果与刷新行为同样保持。最新请求的实际错误按现有错误映射展示。

## 4. 弹窗交互与视觉

### R03 共同布局

- 以会话预览及 [项目设计基线](../../frontend-js/DESIGN.zh-CN.md#弹窗布局)为准，在目标弹窗局部复用 `standard-form-dialog`：标题、内容、页脚三段；标题左侧，整窗操作右侧，标题按 16px、字重 590、行高 1.35，继承主题色和现有组件。
- 标题及页脚保持可达，内容过长时仅内容区滚动。编辑/新增、补建和单项删除确认的「取消」及「保存」或「确认删除」位于右下且有清晰间距；纯查看页脚仅「关闭」。长文案及窄屏可换行、无页面横向溢出，正文/错误/操作不被遮挡。参考预览避免重复的右上关闭入口，保留明确的页脚取消/关闭和非忙碌时 Escape。
- 模态弹窗有可访问标题、清楚的输入标签及可见焦点；Tab/Shift-Tab 可达，关闭后焦点返回合理的触发位置。字段单项保存/删除期间沿用现有禁止重复提交和关闭保护；详情保存按 R01 防重复并保护关闭或离开后的界面归属。校验及服务端错误可读，失败保留当前草稿。明暗主题及中英文使用现有主题和 i18n，不引入全局样式修改。

### R04 详情结构

- 标题识别计划/实绩与当前记录，读取状态和权限有效后，标题右侧显示适用的「编辑」「补建计划」。内容按「基本信息」「业务字段」「时间信息」分组，在空间足够时双列、窄屏单列；组内显示实际数据并保证长值可读。
- 编辑内容使用同一记录的草稿和现有字段控件及规则，不把模拟示例中的固定字段替代真实动态字段。详情与编辑切换不发写请求；编辑取消、失败和重新打开应保持身份清晰。补建继续使用当前既有表单和真实计划字段配置。

### R05 单字段新增、编辑与删除

- 新增与单项编辑按预览分为「字段定义」「使用设置」「计划显示与编辑」「实绩显示与编辑」等适用分组。字段键、槽位、类型、单位、中英文名称及所有现有适用开关/顺序均可找到，不因重新分组丢失数据或功能。计划本地只展示计划相关设置；实绩本地只展示实绩相关设置；共享字段展示两边的适用设置。
- 新增沿用完整组的占槽检查、键/名称校验及现有默认值；已保存字段的稳定键、槽位、类型、单位继续只读。实绩归属、订单快照、回写及实绩可编辑之间的现有禁用/联动保持；空顺序、显式清空和未变更按现有合同区分。单项保存只提交对应字段的实际变化。
- 单行删除需显示真实目标身份与确认文字，提示人工核对外部映射；取消不写入，确认后仍调用当前单项删除接口。是否受使用保护以服务端真实结果为准，不依预览预判可删除；拒绝、修订冲突及原因继续可见。
- 对新增、编辑和删除，保留当前修订检查、保护、草稿、错误信息及 `commit_unknown`/断网后权威重读和人工核对语义，不自动重发或把重读现状断言为请求结果。不得将共享、本地或对侧模块的身份发到错误 scope。

以下均为未来 Development 自检和独立 Verification 的通过条件；测试数据及写请求应使用隔离/合成夹具，不操作真实业务数据库。

| 编号 | 可观察结果 |
| --- | --- |
| AC01 | 计划和实绩各模拟 A 先请求、B 后请求且 B 先返回：A 的主记录或配置分别最后成功/失败，最终仅 B 的身份、值、动态字段、可用操作和 loading 生效，无 A 的错误或成功提示。覆盖主记录与必要配置各自慢/失败，最新失败时旧记录不可操作且可重试或关闭。 |

## 7. 风险、回退及决策记录

- **异步与已提交写入：** 前端失效处理只能阻止旧响应污染界面，不能撤销已经到达服务端的写入；应保留原接口和错误语义，不把网络失败当作确定未提交。
