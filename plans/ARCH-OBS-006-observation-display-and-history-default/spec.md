# 过程曲线按任务号查询最近历史 · r2

## 1. 目标与已验证基线

用户只输入或选择任务号并查询时，系统自动找到该任务最近的可绘制样本，并显示该样本向前八小时的过程曲线。任务历史可能早于首次打开页面时自动填入的时间范围。此前自动填入的来源和时间不能被当成用户对新任务的显式限制。

本 r2 是对 ARCH-OBS-006 r1 的窄范围补充。r1 范围、批准记录及完整原文保留在文末；r1 Development handoff 与独立 QA3 为各自记录中的事实，QA3 为 qa_passed，Human Owner 最终验收仍待明确决定。r1 的结果不自动变成 r2 的开发或 QA 结论。

当前 [过程页面](../../frontend-js/src/app/monitor/views/observations/curves.vue) 首次根据最近锚点自动填来源、任务号和时间。提交时把表单中现存来源与范围视作固定条件，新任务可能沿用旧任务的时段。当前 [默认上下文 API](../../backend/app/equipment_observation/api/routes.py) 只按类别和可选来源找最新锚点，不接受 taskNo。后端的 [任务号规范](../../backend/app/equipment_observation/domain.py) 要求 ASCII，经首尾去空白和转大写后为 1–50 位字母、数字、点、下划线或连字符。

## 2. 交互与状态

### 2.1 未显式指定时间时按任务定位

1. 筛选栏保持设备 / 来源、任务号和采集时间范围。首次进入依旧按 r1 在授权范围内发现最近可绘制样本，并显示实际来源、任务和八小时时段。
2. 用户输入或选择非空任务号，且未主动指定有效时间范围时，点击「查询」向默认上下文接口提交该任务号。上一笔首次加载、恢复默认或任务查询自动带出的时间属于自动范围；即使仍显示在控件中，也不能限制新任务的发现。
3. 用户没有明确选定来源时，在当前用户所有授权且可见的来源中查找该任务的最近可绘制样本。自动发现后填入的来源只是实际结果，不能悄然变成用户主动选定的来源。用户明确选择具体来源后，任务发现严格限定该来源。清除该选择后恢复所有授权来源；即使用户选择的来源恰好与自动展示的来源相同，也必须能表达明确选择。
4. 筛选栏须让来源范围与实际发现来源都可辨认。建议将「全部授权来源」作为范围选项，并在筛选区或状态处显示实际来源名称。该范围选项不向既有 history-curves 传虚构 equipmentId。返回锚点后，使用其真实 equipmentId、规范化 taskNo、from 和 to 请求 history-curves，并让实际来源、任务和范围可见。
5. 精确锚点的 observedAt 即默认结束时间，开始时间为其向前八小时，两端均包含。筛选控件显示上海时间到秒；未编辑的内部 from / to 必须保留服务端返回的微秒。后端不能用服务当前时间、updatedAt、其他任务的时间或其他来源的样本替代。
6. 一次按任务号发现成功并取得曲线后，将其真实来源、任务号和八小时范围作为固定的已应用条件。手动刷新与自动刷新只重读该固定范围，即使后续有新样本也不自动平移；状态展示「当前任务」。用户再次输入另一个任务，尚未手动指定时间时重新按新任务发现，而非沿用上一任务自动产生的范围。

### 2.2 显式时间与既有默认

1. 用户主动修改时间范围时，将其视为显式范围。用户输入或选择任务号后点击「查询」，直接以该任务和用户选择的完整范围查询；不得用发现接口重新选择或替换时间。手工完全清空范围表示重新进入无显式时间状态；只填一端、时间非法或结束早于开始时提示并保留已应用条件。
2. 有显式范围时，使用用户明确选定的来源。用户没有显式选定来源但筛选栏已有自动发现的实际来源时，可使用该当前来源，并在界面清楚显示；若没有可用实际来源，提示选择来源。现有曲线 API 单次按一个来源查询，不能将不同来源的数据拼成同一条曲线或假装一次查询包含全部来源。
3. 未进行任务号查询时，首次加载、跟随最近、手动或自动刷新以及「恢复默认」按 r1 既有行为执行。恢复默认回到跟随最近并清除手工时间；用户若已明确限定来源则保留该范围，否则在授权来源内发现。设备状态四页、曲线布局、指标状态、图例和线型保持 r1 行为。

### 2.3 加载、错误与竞态

1. 查询发出后显示加载状态，不得在响应前显示“无可绘制样本”。任务格式非法、来源无权、目标不可用、曲线未配置和任务无可绘制样本各自清楚提示。无样本提示仅在有效查询成功返回空锚点后出现，不把验证、网络或权限错误说成无数据。
2. 不存在可绘制样本时保留用户输入和来源范围，显示任务无可绘制样本，不以其他任务的曲线或先前结果冒充该任务的结果。查找失败可重试；失败前的结果如保留，须明确仍属于旧的已应用条件。
3. 区分筛选草稿、来源范围意图、时间来源、已应用条件和异步请求代次。相同条件的在途发现查询须合并，重复点击不堆积等价请求。用户提交不同任务、改来源后再次查询、恢复默认或切页时，可使旧请求失效；旧上下文和旧曲线响应不得覆盖新结果，也不得覆盖用户尚未提交的新输入。任务发现期间的手动刷新和自动刷新不能把先前任务恢复成新结果。卸载页面时清理计时器并使在途结果失效。

## 3. 默认上下文接口的向后兼容扩展

在既有 GET /api/v1/monitor/history-default-context 上新增可选查询参数 taskNo。category 和 equipmentId 的原有校验、来源权限与目标 guard 沿用 r1：

| 参数 | r2 行为 |
| --- | --- |
| category | 仍必填，temperature、drive 或 cleaning。 |
| equipmentId | 可省略；省略时在所有授权范围内发现。显式提供时严格限定该设备或来源并检查权限；无权来源不得回退到全范围。 |
| taskNo | 可省略；省略时返回与 r1 相同的默认上下文。显式提供时按现有 task_no 规则验证和规范化，并在按 observed_at DESC、id DESC 选择锚点前，严格过滤该任务。显式空值、纯空白、非 ASCII、非法字符或规范化后超过 50 位，返回既有 invalid_task / 422，不按未提供处理。 |

例如以下请求在授权来源内寻找 DEMO-0001；需要限定来源时，附加该来源真实的 equipmentId：

    GET /api/v1/monitor/history-default-context?category=temperature&taskNo=demo-0001

返回仍使用现有响应信封和字段。示例中的 to 与 observedAt 完全一致，from 向前八小时：

    {
      "code": 200,
      "message": "success",
      "data": {
        "anchor": {
          "equipmentId": "source-or-device-id",
          "taskNo": "DEMO-0001",
          "observedAt": "2026-11-21T08:00:00.123456+08:00",
          "from": "2026-11-21T00:00:00.123456+08:00",
          "to": "2026-11-21T08:00:00.123456+08:00"
        },
        "recentTasks": [
          {"taskNo": "DEMO-0001", "observedAt": "2026-11-21T08:00:00.123456+08:00"}
        ],
        "hasCurves": true
      }
    }

资格判定继续与 r1 一致：只使用当前类别启用的曲线及系列、可见采样组和历史槽位映射；至少一个真实数值可绘制，0 和 unknown 质量可用，缺失、null、非数值以及未配置到可见曲线的较新记录不能占据锚点。按时间与 ID 稳定决胜，ID 只是同刻技术排序，不表示真实采样先后。同刻多个真实样本在后续曲线查询中都保留。

无匹配时保留响应结构，anchor 为 null，recentTasks 为空数组；hasCurves 继续反映该类别是否存在可用曲线配置。该结果不证明数据库没有该任务的其他不可绘制历史。recentTasks 的既有行为继续按所选结果来源、类别和可绘制资格返回最多最近 100 个合格样本去重后的建议，不承诺全量目录；允许用户手工输入旧任务号。

实现应在后端查询条件中限定规范化 taskNo，然后按已有排序取一个结果，不在前端遍历分页或按任意样本数截断后判断无结果。继续采用 monitor-observation-read、已登记且未删除的来源及旧设备读权限。来源无权返回 403，未登录返回 401，非法输入返回 422，目标不可用返回 503；不得因为指定任务扩大授权或泄露其他来源数据。调用时不传 taskNo 的结果、字段与语义必须不变。

r1|
r1|### 2.1 主卡、操作与筛选
r1|
r1|1. 第一栏左侧为现有页面标题。右侧按顺序放当前任务状态、自动刷新开关、刷新按钮。开关始终显示固定名称和可辨认的开关状态，不依赖颜色表达。设备状态初始开启，每五秒按当前已应用条件重查；过程监控初始关闭，开启后同样每五秒刷新。切换页面或销毁组件正确停止旧计时器，同一页面仅保留一个活动计时器。
r1|2. 第二栏为有可见标题的筛选。设备状态包含「设备 / 来源」与「任务号」下拉选择；过程包含「设备 / 来源」「任务号」「采集时间范围」，时间明确为上海时区。按钮「查询」应用当前筛选草稿，「恢复默认」立即恢复本页默认并查询。第一栏的「刷新」只重查已经应用的条件，不提交未点查询的草稿。
r1|3. 用户手动选择任务后，状态标签显示「当前任务」及任务号；跟随最近时显示「最近采样任务」或「最近有数据的任务」及任务号。无任务不捏造任务号。请求失败、无授权来源、无配置与无样本要有可区分的状态；失败不能伪装成无数据。
r1|4. 草稿、已应用条件和异步请求须隔离。切来源、切页、查询、恢复默认、语言切换和快速重复刷新时，迟到响应不能覆盖新结果，也不能让草稿冒充图表条件。一次刷新尚未结束时不得不断堆积请求。刷新不清除已展开的卡片时间、有效的曲线区域及图例选择。
r1|5. 主卡标题、边距、分隔线和响应式布局遵循 [前端设计基线](../../frontend-js/DESIGN.zh-CN.md)。标题栏与内容栏之间的筛选分隔线贴齐主卡左右边界，筛选控件与内容内边距对齐；桌面和窄屏操作可换行，无非表格内容导致的横向页面溢出。遵循现有明暗主题、中英文、菜单和页面权限。
r1|
r1|### 2.2 卡片、时间与值
r1|
r1|1. 卡片使用 B 样式。卡头左侧是管理员配置的标题，右侧只有时钟图标按钮；小卡片及标题分隔线使用当前主题的圆角与浅边框。生产参数桌面四张示例卡以两列呈现，窄屏单列；指标数、卡片数和内容仍由配置决定，不能写死示例或复制原型数据。温控、传动、清洗沿用同一组件和自适应网格。
r1|2. 每张卡的时钟按钮独立控制本卡所有指标下方的采集时间，默认收起，点击再次收起。按钮具有本地化的无障碍名称、Tooltip、aria-expanded，支持 Tab、Enter、Space 和触屏；列表刷新及自动轮询保留该卡的展开状态，切换来源／任务后按稳定卡片和当前数据身份隔离，不把旧来源状态套给新来源。
r1|3. 显示有值指标的真实 item.observedAt，按 YYYY-MM-DD HH:mm:ss、上海时区展示。对 dataState=missing、值为 null 或没有真实 observedAt 的项显示 —，不能用快照的时间冒充该指标的采集事实；保留 0、false 和空字符串的有效含义。当前服务返回的可用项时间就是整包快照时间，不承诺不同槽位可有不同的真实时间。
r1|4. 有效陈旧项以主题警示色的小标签「陈旧」显示，缺测以中性小标签「缺测」显示；正常项不显示状态标签。标签在每项值区靠右对齐内容边线，保留内边距并适应长值换行。其他质量或状态仅在现有接口有明确定义时准确呈现，不把 unknown 显示成良好或主动报警。
r1|5. 布尔值 true 和 false 保持字面值并显示为中性标签，不能根据指标键或中英文名称猜成“运行中”“停止”“有告警”“无告警”。字符串 "true"、"false" 是文本，不被识别成布尔。数字按原小数位规则，单位仍拼在对应指标标题上，原始值不带单位。
r1|
r1|## 3. 过程页面与曲线
r1|
r1|1. 内容由现有 curveGroupKey 配置驱动，已启用且包含所查时段至少一个可绘制数值点的曲线组各有一张圆角浅边框图卡。图卡标题使用配置标题。没有曲线配置、没有来源、当前条件无可绘制样本和请求失败分别提示；无数据时不绘制空坐标轴、空图例或空图卡。
r1|2. 同一个已配置图卡可包含同单位的一个或多个采样区域。多区域图卡的右上显示区域多选和「全选区域」，默认选全部。更改区域只作用于当前图卡。取消全部区域时保留选择控件及“请选择区域”提示，让用户可重新选，不能因为这一操作把整张图卡移除。单区域图卡可省略多余区域控件。刷新时按 groupKey、metricKey 保留仍存在的区域和图例选择；新的区域只有在刷新前已全选时默认选中。
r1|3. 实线与虚线由该系列的明确 lineStyle 决定。图例位于横轴标签之外的独立可换行区域，单区域可只显示指标名，多区域须显示区域名与指标名以区分同名项。图例允许逐线显示或隐藏；隐藏全部线时保留可重新启用的图例和明确提示。悬停展示真实采集时刻与对应值，单位沿用同单位纵轴。画面不得将未取得的数据补成线。
r1|4. 横轴使用 observedAt，缺测形成断点；同刻不同事件都保留，不能用 id、createdAt 或 updatedAt 假设物理先后。跨日范围要让横轴日期可辨认；微秒精度显示限制沿用现有精度提示。任何投影不得将 unknown 质量当作缺测或 good。

r1|## 4. 最近可绘制历史的查询合同
r1|
r1|### 4.1 为什么需要后端调整
r1|
r1|推荐新增只读 GET /api/v1/monitor/history-default-context。它只负责为现有 history-curves 提供真实来源、任务与范围；历史曲线仍由现有曲线 API 返回。现有 history-samples 的单页及类别条件无法判定某条数据在当前启用曲线上有值，前端也不能从有上限的页数推断后续没有更早的有效记录。查询要在后端按既有授权和当前曲线配置完成。
r1|
r1|| 参数 | 规则 |
r1|| --- | --- |
r1|| category | 必填，temperature、drive 或 cleaning。非法值按现有参数错误处理。 |
r1|| equipmentId | 可省略。省略时在当前用户授权的设备及可见登记来源中找最新可绘制样本；显式提供时只在该来源内查，并执行现有来源 / 设备权限校验。显式空值、无效或无权的来源不得扩成全范围。 |
r1|
r1|继续使用 monitor-observation-read、目标 guard 与 history-curves 同源的旧设备范围和未删除登记来源规则。未登录、越权、目标未就绪和非法输入沿用现有 401 / 403 / 503 / 422 约定。无需 admin，不能因全局选择扩大可读来源。无授权来源或无符合条件的样本成功返回空锚点，不伪装为权限错误，也不以服务时间作为采集时间。
r1|
r1|### 4.2 选择、边界和响应
r1|
r1|- 只考虑指定类别中启用的曲线组、该图卡内启用的数值系列、仍可见的启用采样组及有历史槽位映射的指标。历史槽位后来停用写入时，既有曲线读取仍能解释历史；按现有曲线读取语义处理，不能因此删除历史。
r1|- 候选历史样本须在对应 local_values 的组和槽内至少含一个真实可绘制数值。数值零有效，缺组、缺槽、null 和非数值不能充当有效点。quality=unknown 的真实数值仍有效。若最新一条只是同类别中其他组的数据，须继续寻找符合条件的更早样本。
r1|- 按 observed_at DESC, id DESC 稳定确定锚点，id 只用于同刻平局的技术选取，不表示真实采样先后。所选来源和任务都来自该条真实样本，不能跨来源或跨任务拼接。默认 to 为锚点原 observedAt，from 为该时刻向前 8 小时，并且查询该任务；两端包含。保留微秒精度并返回 +08:00，筛选栏显示到秒但未修改的内部查询边界不得丢失微秒。用户手动改时间后按可见输入精度查询。
r1|- 利用现有 (equipment_id, observed_at, id) 时间索引和数据库条件完成资格筛选并以 LIMIT 1 返回锚点，不在浏览器逐页扫历史，也不按任意最近 N 条截断后声称“无数据”。八小时限制的是默认图表时间范围，数据点总量不由时长保证，实施时须用隔离样本验证查询计划与可用性，不做隐式抽样、分页截断或拼接。确有性能瓶颈，先报告并回 PM，不能静默删点或扩展迁移范围。

r1|### 4.3 前端状态
r1|
r1|1. 首次进入过程页先取得权限内来源，再调用默认上下文。返回锚点后，筛选栏实际显示锚点来源、最近任务和八小时时段，再调用 history-curves；不让界面显示一套条件而实际请求另一套。没有锚点时保留可用的筛选控件并显示无样本原因。
r1|2. 用户手动指定任务和 / 或时间点「查询」后，将其作为固定已应用条件；后续手动刷新或自动刷新仅重查它，不自动跳到新任务或改变时间范围。用户在筛选栏手工输入旧任务号时，按该任务和明确范围查询，不从候选中推测替代。若时间范围不完整或结束早于开始，提示并保留上次结果。
r1|3. 默认跟随最近状态下，刷新 / 自动刷新重新查询锚点；有新的有效历史样本时更新已应用的来源、任务和八小时范围。手动选定来源后恢复默认仅在该来源内查最近，提供清空来源后可再次在当前用户授权范围内选最近。无新样本时保留图例和区域选择。两步读取期间若新增数据，后续刷新可见，不把先后两次查询称为原子快照。
r1|4. 用户提交的筛选与锚点查找使用不同请求代次，旧的默认发现、曲线查询和计时器回包不得覆盖新结果。手动 / 自动刷新遵循相同权限和空状态，不修改历史样本。

r1|## 5. 曲线线型的向后兼容配置
r1|
r1|仅扩展过程曲线配置。POST / PATCH /api/v1/monitor/curve-configs 的每个 series 项可选 lineStyle，取值 solid 或 dashed；管理员在现有曲线设置的每项系列旁选择「实线 / 虚线」，新增默认实线。保存成功后现有配置 GET 和 history-curves 对应系列返回该字段，前端按它画线。未携带字段的历史 JSON、历史客户端和旧配置一律可读，展示回退 solid，不自动修改历史配置。
r1|
r1|旧客户端 PATCH 提交 series 时可能省略新字段。对仍保留的同一 metricKey，省略字段沿用该曲线原有线型；新增系列省略时为 solid。显式传入合法值按用户设置更新，非法或 null 值按现有校验拒绝。原系列增删、启用、顺序、同单位和数字类型校验不变。卡片配置的 items 不增加此字段。数据仍存于既有 monitor_curve_group_configs.series JSON，无表结构和历史数据迁移。已有曲线不会自动变虚线，管理员须明确为希望虚线显示的系列配置虚线；这一行为是预览线型在通用配置下的具体落地方式。

r1|## 8. 风险与交接
