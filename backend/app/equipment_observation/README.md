# Equipment observation, process history and energy

[中文](README.zh-CN.md) · [Current machine contract v2](../../../contracts/published/http-api/equipment-observation-v2/README.md) · [r10 specification](../../../plans/ARCH-OBS-001-configuration-driven-equipment-monitoring/spec.md#r10-source-independent-energy) · [User guide](../../../docs/equipment-status-process-monitoring.md#r10-guide)

The manifest registers machine ingestion, human reads and administrator configuration. In r10, SMA, a third party or another authorized program use the same source-independent v2 contract; PLC facts and task-point evidence are not prerequisites. This describes the backend contract, not implementation or operation of a particular SMA or PLC. `sourceRefs` is optional sender-declared metadata, not verified provenance. The published [v1 contract](../../../contracts/published/http-api/equipment-observation-v1/README.md) is historical. The post-retirement source rejects v1 events after identity and scope checks and never replays v1 receipts. The private profile accepts only `c9e1a3b5d720`.

`equipment_status_main` keeps the latest complete multi-group snapshot per equipment and task; `process_monitor_main` appends configured historical measurements for a task; `energy_consumption_main` appends independent meter samples without a task. Events supply their original `observedAt`; the server preserves the event time and converts offset-bearing timestamps to the project time zone. Persistent receipts and independent target/event retries provide idempotency as described in the v2 contract. A latest request can clear omitted groups and therefore requires authorization for its full replacement scope.

Administrators configure regions, stable metric keys, display names, units, cards, curves and history retention separately; the Web uses those settings, not slot numbers or translated titles, to interpret and display values. The external private profile is default-off and supplies machine credential digests and scopes for equipment, targets, groups, metrics and meters. Machine discovery and writes follow those grants; human reads and management use separate permissions and device/meter scope checks. Alembic migrates the schema explicitly; startup and module registration do not create or seed tables. Existing acquisition facts and APIs retain their own contracts and permissions.
